## Which library, for which part of the job

Both libraries draw the same charts. Seaborn calls Matplotlib to do it, returns Matplotlib objects, and modifies Matplotlib's defaults when you set a theme.

The question is never which one to learn. It is which one to reach for at each point in the work.

## The same chart, both ways

Three overlaid distributions in Matplotlib:

```python
fig, ax = plt.subplots(figsize=(7, 4))
for species, group in df.groupby('species'):
    ax.hist(group['body_mass_g'].dropna(), bins=15, alpha=0.5, label=species)
ax.legend()
ax.set_xlabel('Body mass (g)')
```

The same in seaborn:

```python
sns.histplot(df, x='body_mass_g', hue='species', bins=15)
```

Six lines against one, and the seaborn version labels the axis from the column name and builds the legend without being asked.

## Where each is stronger

| Task | Better tool | Why |
| ------------------------------------ | ----------- | ------------------------------------- |
| Grouping by a column | Seaborn | `hue` replaces a loop |
| Splitting into panels by a column | Seaborn | `col` and `row` |
| Statistical charts: box, violin, KDE, regression | Seaborn | Built in, sensible defaults |
| A first look at an unfamiliar dataset | Seaborn | Pair plots and one-line summaries |
| Precise layout of a multi-part figure | Matplotlib | Full control over the grid |
| Axis limits, ticks, formatters | Matplotlib | Seaborn has no equivalent |
| Annotation, reference lines, arrows | Matplotlib | Same |
| A chart type seaborn does not offer | Matplotlib | Anything unusual |
| Finishing any chart for publication | Matplotlib | The adjustments live there |

The pattern down that table is consistent. Seaborn is stronger at getting from a DataFrame to a reasonable chart. Matplotlib is stronger at getting from a reasonable chart to a finished one.

## They are used together

```python
ax = sns.boxplot(df, x='species', y='body_mass_g')
ax.set_title('Gentoos are about 1.4 kg heavier than the other two species')
ax.set_ylabel('Body mass (g)')
ax.axhline(df['body_mass_g'].mean(), color='grey', linestyle='--', linewidth=1)
ax.spines['top'].set_visible(False)
```

One seaborn call for the drawing, four Matplotlib calls for the finishing. This is what most working charts look like, and it is why the previous unit came first.

> Seaborn draws the chart. Matplotlib turns it into the chart you meant. Neither replaces the other, and the returned object is the seam between them.

## What seaborn decides for you

Convenience means defaults, and some of them are statistical choices.

`barplot` shows the mean with a bootstrapped 95% confidence interval. `lineplot` aggregates repeated x values into a mean with a band. `kdeplot` picks a bandwidth. `regplot` fits a straight line whether or not the relationship is straight.

None of these is wrong. All of them are decisions you did not explicitly make, and reporting a chart means knowing what it is showing. The Matplotlib equivalent makes you specify more and therefore hides less.

## Which to write in a notebook

For exploration, seaborn almost always. The charts are throwaway, the defaults are good, and the time saved on each one is spent looking at more of them.

For anything going into a report, start with seaborn if it draws that chart type, then finish in Matplotlib. Rebuild rather than edit, as the visualisation principles unit suggested, so every choice is deliberate.

For a figure with several different chart types in one layout, build the grid with `plt.subplots` and use axes-level seaborn functions inside it.

## What neither does

Interactive charts, maps, network diagrams, and anything a reader is meant to hover over or filter belong elsewhere. That is the subject of the next chapter.

Very large datasets also strain both. Seaborn is slower than Matplotlib because it does more, and a pair plot of a million rows is not a reasonable request of either.

## A working default

Set the theme once at the top of the notebook. Use seaborn for the chart. Take the returned Axes and set the title to your finding, the axis labels to units a reader knows, and the limits explicitly where they matter.

That sequence is about six lines per chart and produces work you can defend, which is the only standard that counts.

## Practise the seam

Count the lines in the original and the rewrite. The saving is real, and the finishing steps are identical either way, which is the whole argument for learning both.
