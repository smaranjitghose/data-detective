## The same data, two shapes

```
     species  female    male
0     Adelie  3368.8  4043.5
1  Chinstrap  3527.2  3939.0
2   Gentoo    4679.7  5484.8
```

```
     species     sex  mean_mass
0     Adelie  female     3368.8
1  Chinstrap  female     3527.2
2     Gentoo  female     4679.7
3     Adelie    male     4043.5
4  Chinstrap    male     3939.0
5     Gentoo    male     5484.8
```

Six numbers, twice. The first is wide: one row per species, one column per sex. The second is long: one row per combination, with the category as a value rather than a column name.

Neither is correct in general. Each suits different work, and converting between them is a routine operation.

## melt goes wide to long

```python
long = wide.melt(id_vars='species', var_name='sex', value_name='mean_mass')
```

| Argument | Meaning |
| ------------ | ----------------------------------------- |
| `id_vars` | Columns to keep as they are |
| `value_vars` | Columns to unpivot, all others by default |
| `var_name` | Name for the new column holding old column names |
| `value_name` | Name for the new column holding the values |

Everything not named in `id_vars` gets stacked into two columns: one holding what used to be the column name, one holding the value.

This is the operation you need when a file arrives with a column per year, per month, or per product, and you want to filter or group by that dimension. You cannot group by something that is spread across column headers.

## pivot goes long to wide

```python
long.pivot(index='species', columns='sex', values='mean_mass')
```

```
sex        female    male
species
Adelie     3368.8  4043.5
Chinstrap  3527.2  3939.0
Gentoo     4679.7  5484.8
```

The round trip returns exactly what we started with. `pivot` is the inverse of `melt`, provided each index and column combination appears once. When it does not, `pivot_table` and an aggregation function are needed instead.

## Which shape for which job

| Task | Shape |
| ---------------------------------- | ----- |
| Reading a summary as a human | Wide |
| Presenting in a report or slide | Wide |
| Grouping or filtering by the category | Long |
| Plotting with a category as colour or facet | Long |
| Storing data that gains new categories over time | Long |
| Computing across a fixed set of columns | Wide |

The plotting row matters more than it looks. Most statistical plotting libraries expect long form, with one column naming the group and one holding the value. A wide table with a column per year has to be melted before it can be plotted with year as a distinguishing feature.

The storage row matters too. A table with a column per month needs its schema changed every month. The long version needs a new row, which is a far smaller operation.

> Wide is for reading. Long is for computing. Most analysis lives in long form and finishes with one melt back to wide for presentation.

## Long form is what tidy data means

Long form is close to the principle usually called tidy data: each variable is a column, each observation is a row, each cell is one value.

A file with columns `sales_2021`, `sales_2022`, `sales_2023` violates it, because year is a variable being stored in the header. Melting it produces `year` and `sales` columns, and everything downstream becomes easier: filtering to one year, grouping by year, adding 2024 next January.

The habit worth carrying is to melt early, do the work, and pivot at the end if a human is going to read it.

## Two practical details

Column names becoming values is a type change. After melting `sales_2021` and `sales_2022`, the new column holds text like `"sales_2021"`, not the number 2021. Extracting the year needs a string operation:

```python
long['year'] = long['variable'].str.extract(r'(\d{4})').astype(int)
```

And melting a wide table with missing cells produces rows holding missing values rather than omitting them. Whether to drop those depends on whether the gap means zero or means unknown, which is the same question the cleaning unit asked.

## Practise the round trip

Take any summary table you have produced.

Melt it to long form, check the row count matches the number of cells you started with, then pivot it back and confirm you get the original.

Then find a real file with a column per period, which is the most common wide format in circulation, and melt it. Everything you want to do with that dataset becomes one line shorter afterwards, which is the practical argument for the shape.
