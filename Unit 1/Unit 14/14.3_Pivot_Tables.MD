## A summary with categories on both axes

A grouped summary with two keys produces a long list. The same information laid out as a grid, with one category down the side and another across the top, is far easier to read.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

df.pivot_table(values='body_mass_g', index='species', columns='sex', aggfunc='mean').round(1)
```

```
sex        female    male
species
Adelie     3368.8  4043.5
Chinstrap  3527.2  3939.0
Gentoo     4679.7  5484.8
```

The same six numbers the two-key groupby produced, arranged so the comparison you care about runs along a row.

## The four arguments

| Argument | What it controls |
| --------- | ------------------------------------ |
| `values` | The column being summarised |
| `index` | What runs down the side |
| `columns` | What runs across the top |
| `aggfunc` | How values are combined, mean by default |

Every pivot table is a grouped aggregation with a different shape. Which category goes on which axis is a readability decision: put the one with fewer distinct values across the top, since wide tables are harder to read than tall ones.

## Margins give the totals

```python
df.pivot_table(values='body_mass_g', index='species', columns='sex',
               aggfunc='mean', margins=True).round(1)
```

```
sex        female    male     All
species
Adelie     3368.8  4043.5  3706.2
Chinstrap  3527.2  3939.0  3733.1
Gentoo     4679.7  5484.8  5092.4
All        3862.3  4545.7  4207.1
```

The `All` row and column give overall figures. Read them carefully: these are means of the underlying rows, not means of the cells.

The Gentoo `All` figure of 5,092.4 differs from the 5,076.0 the plain groupby gave earlier, because the margin excludes the birds whose sex was not recorded while the plain groupby included them. Same species, same column, two defensible numbers, and the difference is which rows each one saw.

That is worth pausing on. A table with margins silently restricts itself to rows having a value on both axes.

## Counts, and filling empty cells

```python
df.pivot_table(values='body_mass_g', index='species', columns='island',
               aggfunc='count', fill_value=0)
```

```
island     Biscoe  Dream  Torgersen
species
Adelie         44     56         51
Chinstrap       0     68          0
Gentoo        123      0          0
```

Changing `aggfunc` to `'count'` turns the summary into a frequency table. `fill_value=0` replaces the empty combinations, which would otherwise show as missing.

The zeros are the finding, and they carry the same message as several earlier units: Chinstraps only on Dream, Gentoos only on Biscoe, and Adelies everywhere.

Note that these counts are of non-missing body mass values, not of rows, so Torgersen shows 51 rather than 52. Choosing `aggfunc='size'` counts rows instead.

## pivot and pivot_table are different

```python
df.pivot(index='species', columns='sex', values='body_mass_g')
```

```
ValueError: Index contains duplicate entries, cannot reshape
```

`pivot` only rearranges. It expects one value per index and column combination, and there are 146 Adelies with a recorded sex rather than one.

`pivot_table` aggregates, which is why it works here. Use `pivot` when your data is already one row per combination and you are only reshaping; use `pivot_table` whenever combining is needed.

> If `pivot` raises a duplicate error, you did not want `pivot`. You wanted to aggregate, and the error is telling you to decide how.

## Several aggregations at once

```python
df.pivot_table(values='body_mass_g', index='species', aggfunc=['mean', 'count']).round(1)
```

```
                 mean       count
          body_mass_g body_mass_g
species
Adelie         3700.7         151
Chinstrap      3733.1          68
Gentoo         5076.0         123
```

Passing a list of functions produces a two-level header. It is precise and cluttered, and for anything more than two functions a named aggregation on a groupby reads better.

## When to reach for a pivot table

Three situations.

Two categorical dimensions and one measure, which is what the shape is built for. A summary that a non-analyst will read, since the grid layout needs no explanation. And a comparison where you want to scan across a row and down a column at the same time.

For anything feeding into further computation, a long-form grouped result is easier to work with, which is the subject of the next topic.

## Practise the layout decision

Take a dataset with two categorical columns and one numeric column.

Build the pivot table both ways round, swapping index and columns, and decide which is more readable.

Then add `margins=True` and check whether the margin figures match a plain groupby on the same column. Where they differ, find the rows that are missing a value on one of the two axes. That check takes two minutes and prevents quoting two different numbers for the same quantity in one report.
