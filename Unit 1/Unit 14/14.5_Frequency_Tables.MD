## Counting combinations of two categories

Two category columns and a question: how do they occur together? That is a frequency table, and `crosstab` builds one directly.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

pd.crosstab(df['species'], df['island'])
```

```
island     Biscoe  Dream  Torgersen
species
Adelie         44     56         52
Chinstrap       0     68          0
Gentoo        124      0          0
```

Counts of rows in each combination. `crosstab` takes the two Series directly rather than a DataFrame and a column name, which makes it slightly different in form from everything else in this unit.

## Proportions matter more than counts

Raw counts confound group size with pattern. A category with more rows shows larger numbers everywhere.

```python
pd.crosstab(df['species'], df['island'], normalize='index') * 100
```

```
island     Biscoe  Dream  Torgersen
species
Adelie       28.9   36.8       34.2
Chinstrap     0.0  100.0        0.0
Gentoo      100.0    0.0        0.0
```

Each row now sums to 100. The reading is direct: Adelies split roughly evenly across three islands, while the other two species are entirely on one island each.

| `normalize` | Each what sums to 1 |
| ----------- | ------------------- |
| `'index'` | Row |
| `'columns'` | Column |
| `'all'` | The whole table |

The choice is not cosmetic. Row proportions answer "given the species, which island", and column proportions answer "given the island, which species". Those are the two conditional probabilities from the earlier unit, and they give different numbers.

> Normalising by row and by column answers two different questions. Deciding which you meant before reading the table is what keeps you from stating the reverse of your finding.

## Margins

```python
pd.crosstab(df['species'], df['sex'], margins=True)
```

```
sex        female  male  All
species
Adelie         73    73  146
Chinstrap      34    34   68
Gentoo         58    61  119
All           165   168  333
```

The grand total is 333, not 344. Eleven birds have no recorded sex, and `crosstab` drops rows missing either variable without saying so.

That gap between the table total and the file length is worth checking every time. A frequency table that quietly covers 97% of your data is fine as long as you know it does.

## Summarising a value instead of counting

```python
pd.crosstab(df['species'], df['sex'], values=df['body_mass_g'], aggfunc='mean').round(1)
```

```
sex        female    male
species
Adelie     3368.8  4043.5
Chinstrap  3527.2  3939.0
Gentoo     4679.7  5484.8
```

Supplying `values` and `aggfunc` turns a frequency table into an aggregation, which is exactly what `pivot_table` does. The two overlap almost completely here.

The practical difference is that `crosstab` defaults to counting and takes Series, while `pivot_table` defaults to averaging and takes a DataFrame. Use whichever reads better for the question you are asking.

## Reading a frequency table for structure

Three things to look for, and each has appeared elsewhere in the course.

Zeros mean a combination does not occur. The four zeros in the species-island table mean questions like "are Chinstraps heavier on Biscoe" cannot be answered at all, because there are no Chinstraps on Biscoe.

Very small cells mean a comparison is unsupported. A cell with three rows will produce an average, and it will move wildly if one row changes.

And a strong pattern in a frequency table means the two variables travel together, which is the warning that any relationship you find involving one of them may be about the other. The species and island table is the reason the bill length and depth correlation reversed when species was accounted for.

## When there are more than two variables

```python
pd.crosstab([df['species'], df['sex']], df['island'])
```

Passing a list gives a hierarchical index, one level per variable. It works, and it becomes unreadable quickly.

Beyond three variables, a grouped aggregation in long form is easier to work with and easier to read than a deeply nested table.

## Practise both normalisations

Take two category columns from any dataset and build the raw crosstab.

Then build it normalised by index and by column, and write one sentence from each. The two sentences should say noticeably different things.

Then add `margins=True` and compare the grand total against the row count of your file. Any shortfall is rows missing a value on one of the two columns, and knowing the size of it is part of reporting the table honestly.
