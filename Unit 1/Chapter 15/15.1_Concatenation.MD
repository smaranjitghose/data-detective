## Stacking tables that share a shape

Monthly exports, one file per region, a year of daily logs. When several tables hold the same kind of record, combining them means stacking rows.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

parts = [g for _, g in df.groupby('year')]      # three tables: 110, 114, 120 rows
stacked = pd.concat(parts, ignore_index=True)
stacked.shape                                    # (344, 8)
```

Three tables in, one table out, and the row count matches the original exactly.

## ignore_index, and why it matters

Each part carried its own index labels from the original file. Without `ignore_index=True`, those labels come along, and the combined table has an index that repeats.

Duplicate index labels break things quietly. `loc` lookups return several rows instead of one, joins misbehave, and any operation aligning on the index produces surprises.

Pass `ignore_index=True` when the original labels mean nothing, which is the usual case for stacked files.

## Columns are matched by name, not position

```python
a = df.head(2)[['species', 'body_mass_g']]
b = df.head(2)[['species', 'flipper_length_mm']]
pd.concat([a, b])
```

```
  species  body_mass_g  flipper_length_mm
0  Adelie       3750.0                NaN
1  Adelie       3800.0                NaN
0  Adelie          NaN              181.0
1  Adelie          NaN              186.0
```

The result has the union of both column sets, with missing values wherever a table lacked a column.

This is the behaviour that turns a small naming inconsistency into a large mess. One file calling a column `mass_g` while the others call it `body_mass_g` produces two columns, each half empty, and no error.

> A block of missing values appearing after a concat almost always means the source tables disagreed about a column name.

## Checking after stacking

Two checks catch most problems.

```python
len(stacked) == sum(len(p) for p in parts)      # rows are all there
stacked.isna().sum()                            # unexpected gaps
```

If the row count matches and no new gaps appeared, the stack worked. If gaps appeared, compare the column names of each part before looking anywhere else.

Recording where each row came from is worth the one extra line:

```python
for name, part in zip(names, parts):
    part['source_file'] = name
```

Six months later, when one region's numbers look wrong, that column is how you find which file they came from.

## Horizontal concatenation

```python
pd.concat([df.head(2)[['species']], df.head(2)[['body_mass_g']]], axis=1)
```

```
  species  body_mass_g
0  Adelie       3750.0
1  Adelie       3800.0
```

With `axis=1` the tables are placed side by side, matched by index.

That matching is the trap. Two tables with different index labels do not line up by position; they align by label, and every unmatched label produces a row of gaps:

```python
x = df.head(3)[['species']]        # index 0, 1, 2
y = df.iloc[1:4][['body_mass_g']]  # index 1, 2, 3
pd.concat([x, y], axis=1)
```

```
  species  body_mass_g
0  Adelie          NaN
1  Adelie       3800.0
2  Adelie       3250.0
3     NaN          NaN
```

Three rows and three rows produced four, with gaps at both ends. Nothing is wrong with the operation; the two tables simply did not describe the same records.

When you mean to attach columns for the same records, use `merge` on a key. Horizontal concat is for cases where you are certain the indexes correspond.

## When to concat and when to merge

| Situation | Use |
| ------------------------------------------- | --------- |
| Same columns, more rows | `concat` |
| Different columns for the same records | `merge` |
| Files split by month, region, or batch | `concat` |
| Attaching a lookup table | `merge` |
| Two tables with a shared identifier column | `merge` |

The rule of thumb: concat when the tables are the same shape of thing, merge when one table adds information about the other's rows.

## Practise the column check

Split any dataset into three parts, rename one column in one of the parts, and concat them.

Check the shape and the missing counts. You will find two half-empty columns where you expected one full one.

Then write the check you would run to catch it automatically: comparing the column set of each part against the first before combining. Three lines, and it prevents the most common concat failure.
