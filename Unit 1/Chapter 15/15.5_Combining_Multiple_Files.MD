## A folder of files into one table

Data arrives split: one file per month, per region, per batch, per export. The task is routine and has a few reliable traps.

```python
import pandas as pd, glob, os

files = sorted(glob.glob('parts/penguins_*.csv'))
```

```
['penguins_2007.csv', 'penguins_2008.csv', 'penguins_2009.csv']
```

`sorted` matters. `glob` returns files in whatever order the filesystem gives, which is not alphabetical and not stable across machines. Sorting makes the result reproducible.

## The pattern

```python
frames = []
for f in files:
    d = pd.read_csv(f)
    d['source_file'] = os.path.basename(f)
    frames.append(d)

all_df = pd.concat(frames, ignore_index=True)
all_df.shape          # (344, 9)
```

Read each file, tag it with its origin, collect into a list, concatenate once at the end.

Two details carry most of the value. The `source_file` column means every row can be traced back, which is what you need when one file turns out to be wrong. And concatenating once rather than inside the loop avoids copying the whole growing table on every iteration.

## Verify against the parts

```python
all_df.groupby('source_file').size()
```

```
penguins_2007.csv    110
penguins_2008.csv    114
penguins_2009.csv    120
```

Three files, 344 rows, and the per-file counts add up. That table is the first thing to look at after any multi-file load, and it catches a file that failed to read, one that was read twice, and one that is unexpectedly empty.

## The failure that does not raise an error

Add a fourth file where one column has a different name:

```python
combined.shape                          # (454, 9)
combined['body_mass_g'].isna().sum()    # 112
combined['mass_g'].isna().sum()         # 345
```

The file used `mass_g` instead of `body_mass_g`. Concatenation matched columns by name, found two different names, and produced two columns, each mostly empty.

No error. The shape looks plausible. Every summary of body mass now silently excludes one file's rows.

> Column names drifting between files is the defining problem of multi-file loading, and concatenation will never tell you it happened.

## Checking before you combine

Compare the column sets before concatenating, which takes four lines:

```python
schemas = {f: set(pd.read_csv(f, nrows=0).columns) for f in files}
first = next(iter(schemas.values()))
for f, cols in schemas.items():
    if cols != first:
        print(f, 'differs:', cols ^ first)
```

Reading with `nrows=0` loads only the header, so this is fast even on large files.

The symmetric difference shows exactly which names are unique to one side, which is usually enough to write the rename that fixes it.

## Other things that differ between files

| Difference | Symptom | Fix |
| ---------------------- | -------------------------------- | -------------------------------- |
| Column names | Half-empty duplicate columns | Rename before concatenating |
| Column order | None, names are matched | Nothing needed |
| Types | A numeric column becomes text | Convert after loading |
| Date formats | Mixed or wrong dates | Parse per file with explicit format |
| Encodings | UnicodeDecodeError on one file | Set `encoding` for that file |
| An extra header row | One row of text in the data | `skiprows` for that file |

The type row is worth expanding. If one file has a stray text value in a numeric column, that file's column loads as text, and the concatenated column becomes text overall. Every arithmetic operation then fails, and the traceback points at the combined table rather than at the file that caused it.

Checking `dtypes` per file, alongside the column names, catches it at the right moment.

## When files are too large together

If the combined table will not fit in memory, the pattern changes: process each file separately, keep only what you need from each, and combine the results.

```python
summaries = []
for f in files:
    d = pd.read_csv(f, usecols=['species', 'body_mass_g'])
    summaries.append(d.groupby('species')['body_mass_g'].agg(['sum', 'count']))
combined = pd.concat(summaries).groupby(level=0).sum()
```

Sums and counts combine across files; means do not. Averaging the per-file averages gives the wrong answer unless every file has the same number of rows, which is why the sum and count are carried separately and divided at the end.

## Practise the schema check

Split a dataset into four files, rename one column in one of them, and combine them with the plain loop.

Look at the shape and the missing counts, and confirm you can see the damage.

Then write the header comparison and run it before the loop. Four lines that turn a silent failure into a printed warning, and the habit generalises to every folder of files you will ever be handed.
