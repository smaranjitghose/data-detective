## Attaching information from another table

Two tables describe the same things from different angles. Orders and customers. Marks and students. Measurements and a lookup of what each code means.

`merge` combines them on a shared key.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

lookup = pd.DataFrame({'species': ['Adelie', 'Chinstrap', 'Gentoo'],
                       'latin': ['Pygoscelis adeliae',
                                 'Pygoscelis antarcticus',
                                 'Pygoscelis papua']})

m = df.merge(lookup, on='species', how='left')
m.shape          # (344, 9)
```

```
  species               latin
0  Adelie  Pygoscelis adeliae
1  Adelie  Pygoscelis adeliae
```

344 rows in, 344 rows out, one new column. The three lookup rows were matched against 344 penguin rows, each bird receiving the Latin name for its species.

## The four join types

The join type decides what happens to rows with no match on the other side.

Take a lookup covering only two of the three species:

```python
partial = pd.DataFrame({'species': ['Adelie', 'Gentoo'], 'diet': ['krill', 'fish']})
```

| `how` | Rows | Missing diet |
| ------- | ---: | -----------: |
| `left` | 344 | 68 |
| `inner` | 276 | 0 |
| `right` | 276 | 0 |
| `outer` | 344 | 68 |

Read those numbers against the file. The 68 Chinstraps have no entry in the lookup, so a left join keeps them with a gap in the new column, and an inner join drops them entirely.

| Join | Keeps |
| ------- | ------------------------------------------ |
| `left` | Every row of the left table |
| `right` | Every row of the right table |
| `inner` | Only rows matching in both |
| `outer` | Every row of both, gaps where unmatched |

## Left is the safe default

A left join preserves your row count, which means you can check it.

```python
before = len(df)
after = len(df.merge(lookup, on='species', how='left'))
before == after
```

An inner join silently discards unmatched rows, and a merge that drops 68 birds looks identical to one that drops none unless you compare the counts.

The habit: use a left join, then count the gaps in the new column. That number tells you exactly how many rows failed to match, which an inner join would have hidden by removing them.

## The indicator column shows what happened

```python
r = df.merge(partial, on='species', how='left', indicator=True)
r['_merge'].value_counts()
```

```
both          276
left_only      68
right_only      0
```

`indicator=True` adds a column recording, per row, which side it came from. It is the fastest diagnostic in the whole topic: 276 matched, 68 found nothing, and no lookup rows went unused.

`right_only` being zero matters too. A non-zero value means your lookup contains keys absent from the data, which is often a sign the lookup is for a different period or population.

> Run every important merge with `indicator=True` first and read the three counts. If they are not what you expected, stop before using the result.

## Keys with different names

```python
df.merge(other, left_on='species', right_on='species_name', how='left')
```

Use `left_on` and `right_on` when the columns are named differently. Both columns survive into the result, so one usually gets dropped afterwards.

For several key columns, pass a list: `on=['student_id', 'subject']`. All named columns must match for a row to join.

## Joining on the index

```python
df.merge(other, left_index=True, right_index=True)
df.join(other)
```

`join` is a shorthand for merging on the index, and it defaults to a left join. It reads well when both tables are indexed by the same identifier, and `merge` does everything it does.

## Overlapping column names

When both tables have a column of the same name that is not a key, pandas adds suffixes.

```python
df.merge(other, on='species', suffixes=('_measured', '_reference'))
```

The default suffixes are `_x` and `_y`, which are unmemorable. Setting them explicitly makes the result readable and prevents the common confusion of not knowing which `value_x` came from where.

## Practise the count check

Take any dataset and build a small lookup table covering some but not all of its key values.

Merge with all four join types and record the row count each time. Then run the left join with `indicator=True` and confirm the counts explain the differences.

Then deliberately drop a value from the lookup and repeat. Watching the `left_only` count rise by exactly the number of rows with that key is what makes the diagnostic trustworthy.
