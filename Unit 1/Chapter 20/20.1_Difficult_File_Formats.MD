## Files that do not open cleanly

The penguin file loads in one call because someone prepared it for teaching. Files from a government portal, an internal system, or a partner organisation arrive in states that `read_csv` cannot guess.

Three problems account for most of them.

## Encodings

```python
pd.read_csv('data.csv', encoding='ascii')
```

```
UnicodeDecodeError: 'ascii' codec can't decode byte 0xc3 in position 23
```

Text files store characters as bytes, and the mapping between them is the encoding. Read a file with the wrong one and you get either an error or, worse, silently wrong characters.

UTF-8 is the modern default and handles every script, including Devanagari and Tamil:

```
        city          name
0  Bengaluru  José Márquez
1      मुंबई           Raj
```

Files exported from older Windows software are frequently `latin-1` or `cp1252`. Those encodings cover Western European characters and nothing else.

| Symptom | Likely cause | Try |
| ---------------------------------- | -------------------- | ----------------- |
| `UnicodeDecodeError` | Not UTF-8 | `encoding='latin-1'` |
| Names read as `JosÃ©` | UTF-8 read as latin-1 | `encoding='utf-8'` |
| Indian language text as question marks | Encoding lost at export | Ask for a new export |

The second row is the dangerous one, because it does not raise an error. A file that loads with mangled accented characters has been read with the wrong encoding, and the mangling is permanent if you save it that way.

`latin-1` never fails on any byte sequence, which makes it a useful last resort and a poor first choice: it will read anything and may read it wrongly.

## Multi-sheet Excel

```python
sheets = pd.read_excel('report.xlsx', sheet_name=None)
list(sheets.keys())
```

Passing `sheet_name=None` returns a dictionary of every sheet, which is how you find out what a workbook contains before deciding what to load.

Excel files carry problems CSVs do not. Merged cells produce missing values in unexpected places. A title row above the header needs `skiprows`. Numbers stored as text with a green triangle in Excel arrive as text here. And a sheet with a total row at the bottom will be read as data unless you remove it.

```python
pd.read_excel('report.xlsx', sheet_name='Data', skiprows=3, usecols='B:H')
```

`usecols` accepts Excel column letters, which is often easier than naming columns when the header itself is messy.

## Nested JSON

```python
pd.read_json('readings.json')
```

```
       station                                    readings                      meta
0  Anand Vihar  [{'pollutant': 'PM2.5', 'value': 412}, ...]  {'city': 'Delhi', ...}
```

Two of the three columns contain Python objects rather than values. Nothing can be computed from them.

```python
pd.json_normalize([nested], record_path='readings',
                  meta=['station', ['meta', 'city']])
```

```
  pollutant  value      station meta.city
0     PM2.5    412  Anand Vihar     Delhi
1      PM10    580  Anand Vihar     Delhi
```

`json_normalize` flattens the structure. `record_path` names the list to expand into rows, and `meta` names the fields to carry down onto each of those rows, with a list for anything nested.

The result has one row per reading rather than one per station, which is the shape you can actually work with.

> A JSON column containing dictionaries or lists is not data yet. Every operation on it will either fail or silently treat the object as a single value.

## Reading the file before pandas does

For any file that fights you, look at the raw bytes first:

```python
with open('data.csv', 'rb') as f:
    print(f.read(500))
```

Reading in binary mode shows the delimiter, the line endings, whether there is a byte order mark at the start, and whether the header is on the first line. Thirty seconds there saves twenty minutes of guessing at parameters.

Try the plain `read_csv` first and record what breaks. Then open the first 500 bytes in binary mode and work out which parameters you need.
