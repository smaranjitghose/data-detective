## When the file is bigger than your memory

pandas holds everything in memory. A file that exceeds your available RAM will not load, and the practical ceiling arrives well before the theoretical one, because operations make copies.

Three techniques cover almost all of it: reduce what you load, reduce what each column costs, and process in pieces.

## Find out what it actually costs

```python
df.memory_usage(deep=True)
```

```
Index                  132
species              19124
island               18952
bill_length_mm        2752
bill_depth_mm         2752
flipper_length_mm     2752
body_mass_g           2752
sex                  18331
year                  2752
```

```
total: 68.7 KB
```

The `deep=True` matters. Without it, text columns report only the size of the pointers rather than the strings they point to, which understates them by an order of magnitude.

Look at the numbers. The three text columns take 56 KB of the 69, and the four measurement columns take 11 KB between them. Text is where the memory goes.

## Choosing better types

```python
for c in ['species', 'island', 'sex']:
    d[c] = d[c].astype('category')
d['year'] = d['year'].astype('int16')
for c in ['bill_length_mm', 'bill_depth_mm', 'flipper_length_mm', 'body_mass_g']:
    d[c] = d[c].astype('float32')
```

```
before: 68.7 KB
after:   7.6 KB
```

Nine times smaller, with no information lost.

The category conversion does most of it. A text column stores the full string for every row; a category stores each distinct value once plus a small code per row. With three distinct species across 344 rows, that is a large saving, and on a million-row file with a handful of categories it is the difference between working and not.

| Conversion | When it is safe |
| ---------------------- | ------------------------------------------- |
| Text to `category` | Few distinct values relative to row count |
| `int64` to `int16` | Values fit in the smaller range |
| `float64` to `float32` | Seven significant digits are enough |

`float32` is the one to think about. It carries about seven significant digits against sixteen, which is plenty for physical measurements and not enough for accumulating millions of values, where rounding errors compound.

## Loading less

```python
pd.read_csv('big.csv', usecols=['species', 'body_mass_g'])
pd.read_csv('big.csv', dtype={'species': 'category'})
pd.read_csv('big.csv', nrows=1000)
```

The cheapest saving is not loading columns you will not use. A forty-column file where your question needs four is a tenfold reduction before anything else.

Passing `dtype` at read time applies the conversions above during loading rather than afterwards, which avoids ever holding the expensive version.

And `nrows` is how every session with an unfamiliar large file should start: load a thousand rows, look at the columns and types, then decide what the full load should specify.

## Chunking

```python
total = 0
count = 0
for chunk in pd.read_csv('penguins.csv', chunksize=100):
    total += chunk['body_mass_g'].sum()
    count += chunk['body_mass_g'].count()

total / count      # 4201.75
```

The direct mean is 4201.75. The chunked calculation gives the same answer without ever holding the whole file.

`chunksize` returns an iterator of DataFrames. Each is a normal DataFrame that you process and discard.

The pattern only works for calculations that combine across chunks. Sums and counts do; means do not, which is why the code above carries both and divides at the end. Medians and quantiles cannot be computed this way at all, since they need every value at once.

| Operation | Chunkable |
| ------------------ | -------------------------- |
| Sum, count, min, max | Yes |
| Mean | Yes, via sum and count |
| Group sums and counts | Yes, combine the per-chunk results |
| Median, quantiles | No |
| Sorting the whole file | No |
| Deduplication | Only within a chunk |

## Sampling

```python
sample = df.sample(50, random_state=1)
sample['body_mass_g'].mean()      # 4237.0, against 4201.8 for all 342
```

For exploration, a sample is often enough. Fifty of 342 birds gives a mean within 1% of the full figure, and every chart drawn on it looks the same.

Sample early, explore freely, and run the final numbers on everything. Always set `random_state` so the sample is the same on the next run.

The caveat is rare events. A sample of 1% will miss most of a category that makes up 0.1% of the file, which is exactly the category a fraud or failure analysis is about.

> Sampling is safe for understanding the shape of a dataset and unsafe for anything about its rare cases.

## When pandas is the wrong tool

Beyond a few gigabytes, other tools are designed for the job: Polars for a similar interface with better memory behaviour, DuckDB for querying files larger than memory with SQL, and Dask or Spark for work spread across machines.

Converting a CSV to Parquet also helps considerably. It is columnar, so reading four columns of forty reads only those four from disk, and it is compressed and typed.

## Practise the reduction

Take any dataset and measure `memory_usage(deep=True)` before and after converting its text columns to categories and downcasting its numerics.

Then compute a mean two ways: directly, and with `chunksize` set small enough to produce several chunks.

If the two means differ, you have averaged the chunk averages instead of carrying sums and counts, which is the single most common error in chunked processing.
