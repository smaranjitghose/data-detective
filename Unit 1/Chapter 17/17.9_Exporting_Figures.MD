## Getting the chart out of the notebook

A figure that exists only in a notebook cell cannot go into a report, a slide, or an email. Saving it is one call with a few decisions attached.

```python
fig.savefig('mass_by_species.png', dpi=300, bbox_inches='tight')
```

Three arguments, and each one addresses a specific problem.

## Format

| Format | Kind | Suits | Note |
| ------ | ------ | ---------------------------- | ------------------------------ |
| PNG | Pixels | Slides, web, email | Fixed resolution, set dpi |
| SVG | Vector | Web, any size | Scales without blurring |
| PDF | Vector | Print, LaTeX documents | Scales, embeds fonts |
| JPG | Pixels | Photographs | Poor for charts, blurs edges |

The format is chosen by the file extension you give.

Saving the same 8 by 5 inch figure four ways gives an idea of the trade:

```
test_100.png     38.7 KB
test_300.png    141.4 KB
test.svg         27.9 KB
test.pdf         12.0 KB
```

Vector formats are smaller here and stay sharp at any size, because they store the drawing instructions rather than a grid of pixels. They grow with the number of elements, so a scatter plot of a hundred thousand points produces an enormous SVG while its PNG stays the same size.

That is the practical rule: vector for most charts, PNG for anything with very many points.

## Resolution

```python
fig, ax = plt.subplots(figsize=(8, 5))     # 8 by 5 inches
fig.savefig('out.png', dpi=300)            # 2400 by 1500 pixels
```

Figure size is in inches and dpi converts it to pixels. The default of 100 gives 800 by 500, which looks fine on screen and blurry when projected or printed.

| Destination | dpi |
| ----------------- | --- |
| Screen, notebook | 100 |
| Slides | 150 to 200 |
| Print, publication | 300 |

Raising dpi does not change the layout. Text and lines keep the same proportions and are drawn with more pixels, which is why the figure should be sized for its destination at creation rather than scaled afterwards.

Scaling a saved PNG up in a document blurs it. Scaling a figure by changing `figsize` and re-saving keeps everything crisp.

## Cropping

```python
fig.savefig('out.png', bbox_inches='tight')
```

Without it, the saved file includes the default margins, which are generous. With it, the file is cropped to the drawn content, which usually looks better when placed in a document.

Add `pad_inches=0.1` if the crop is too tight against the labels.

## Transparency

```python
fig.savefig('out.png', transparent=True)
```

Saves without the white background, so the chart sits on whatever colour the slide or page uses.

Worth knowing and worth checking, since dark text on a dark slide background disappears, and the fix is to set the text colour rather than the background.

## Saving before showing

In a script, `plt.show()` opens a window and, on some backends, clears the figure. A `savefig` call after it can produce a blank file.

Save first, then show. In notebooks the ordering rarely bites, and the habit costs nothing.

## Reproducibility

A saved chart carries no record of what produced it. Three months later, the questions are which data version, which filter, and which script.

Two practices cover most of it. Save the figure from the same script that produced the data, so the chart cannot drift from the numbers. And give the file a name that identifies the content rather than the sequence, since `mass_by_species_v3.png` is findable and `chart2.png` is not.

> A chart in a report is a claim about data. If you cannot regenerate it from a script in one command, you cannot check the claim when someone questions it.

## Closing figures

```python
plt.close(fig)
```

Figures stay in memory until closed. A loop generating a hundred charts will warn you after twenty, and the fix is to close each one after saving.

## Practise the destination

Take one chart and save it four ways: PNG at 100 dpi, PNG at 300, SVG, and PDF.

Compare the file sizes, then open each at 400% zoom and look at the text.

Then place the 100 dpi version and the 300 dpi version into a slide at the same displayed size. The difference is what dpi buys, and seeing it once fixes the setting in your habits.
