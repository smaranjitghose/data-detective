## Two objects, and why every tutorial disagrees

Search for a Matplotlib example and you will find two styles that look unrelated.

```python
plt.plot(x, y)
plt.title('Something')
```

```python
fig, ax = plt.subplots()
ax.plot(x, y)
ax.set_title('Something')
```

Both work. The first is shorter and the second is what you should write, and understanding why takes one idea.

## Figure and Axes

```python
import matplotlib.pyplot as plt
fig, ax = plt.subplots(figsize=(8, 5))
type(fig), type(ax)      # Figure, Axes
```

A Figure is the whole canvas: the page you will save. An Axes is one plotting area inside it, with its own x axis, y axis, title, and data.

The naming is unfortunate. An Axes is not an axis; it is a complete plot, and a Figure can hold several of them.

| Object | Owns | Typical methods |
| ------ | ------------------------------- | ------------------------------------- |
| Figure | The canvas, size, saving, overall title | `savefig`, `suptitle`, `tight_layout` |
| Axes | One plot: data, labels, limits, legend | `plot`, `bar`, `set_title`, `set_xlim` |

## What the two styles actually are

The `plt.` functions operate on whichever Axes is currently active. Matplotlib keeps a hidden pointer to it, and every `plt.title()` call means "set the title of whatever I am pointing at".

That works for a single plot and breaks as soon as there are two, because you now have to track which one is current and in what order things were created.

The object-oriented style names the object:

```python
fig, ax = plt.subplots()
ax.plot(a['Date'], a['AAPL.Close'])
ax.set_title('Closing price')
```

Nothing is implicit. In a notebook where cells run out of order, that difference is the difference between a chart that reappears correctly and one that mysteriously attaches its title to the wrong figure.

> Write `fig, ax = plt.subplots()` as the first line of every chart. It costs one line and removes an entire category of confusion.

## The naming convention

Method names follow a pattern that makes them guessable.

| Property | Axes method |
| ------------- | ------------------------ |
| Title | `ax.set_title('...')` |
| X axis label | `ax.set_xlabel('...')` |
| Y axis limits | `ax.set_ylim(0, 100)` |
| Legend | `ax.legend()` |
| Grid | `ax.grid(True)` |

The `plt.` equivalents drop the `set_`, which is why `plt.title()` and `ax.set_title()` look different while doing the same thing. Once you know the rule, translating any tutorial into the object-oriented style is mechanical.

## Figure size and what it means

```python
fig, ax = plt.subplots(figsize=(8, 5))
```

The figure size is given in inches, and the default is 6.4 by 4.8. Combined with dots per inch, it determines the pixel dimensions: at the default of 100 dpi, a figure of 8 by 5 inches is 800 by 500 pixels.

Inches feel strange on screen and make sense at the destination. A figure sized for a slide differs from one sized for a printed page, and setting the size at creation rather than resizing afterwards keeps the text proportions correct.

## Several plots in one figure

```python
fig, axes = plt.subplots(2, 3, figsize=(12, 6))
axes.shape        # (2, 3)
```

The same call returns an array of Axes when you ask for more than one. Each element is a complete plot, addressed as `axes[0, 1]`, and each is drawn independently.

This is where the implicit style falls apart entirely, and it is the main practical argument for the explicit one.

## Showing and closing

In a notebook, a figure displays automatically at the end of a cell. In a script, `plt.show()` opens a window.

Figures accumulate in memory until closed, so a loop producing fifty charts will eventually warn you about it. `plt.close(fig)` after saving is the fix, and it matters only when generating charts in bulk.
