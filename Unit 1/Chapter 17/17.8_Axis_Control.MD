## Deciding what the axes show

Matplotlib chooses axis limits, tick positions, and label formats automatically. Those defaults are chosen to make the data fill the frame, which is not the same as making the chart honest or readable.

## Limits

```python
ax.set_ylim(0, 6000)
ax.set_xlim(pd.Timestamp('2016-01-01'), pd.Timestamp('2016-12-31'))
```

Setting limits does two jobs: enforcing a zero baseline on bar charts, and zooming into a region of interest.

The bar chart case is the one that matters most, for the reason the misleading graphics topic established. Left to itself, Matplotlib will start a bar chart's axis wherever the data suggests, and three means of 3,701, 3,733, and 5,076 grams will be drawn with a baseline near 3,600, turning a true ratio of 1.37 into an apparent one of 14.61.

Setting `set_ylim(0, ...)` explicitly on every bar chart is a one-line habit that removes the problem.

## Log scales

```python
ax.set_yscale('log')
```

A logarithmic scale spaces the axis by ratio rather than by difference, so equal distances represent equal multiplications: 1 to 10 occupies the same space as 10 to 100.

It is the right choice for data spanning several orders of magnitude, which the distributions unit called power-law shaped. City populations, incomes, file sizes, and website traffic all compress into an unreadable spike at the low end on a linear axis and become legible on a log one.

| Situation | Scale |
| ----------------------------------- | ------ |
| Values within one order of magnitude | Linear |
| Values spanning three or more | Log |
| Growth rates, where doubling matters | Log |
| Any value that can be zero or negative | Linear, since log cannot represent them |

A log axis needs labelling as such. Readers assume linear, and a chart where a small visual rise means a tripling will be misread by anyone who did not check.

## Tick positions and labels

```python
ax.set_xticks([0, 1, 2])
ax.set_xticklabels(['Adelie', 'Chinstrap', 'Gentoo'])
ax.tick_params(axis='x', rotation=45)
```

`set_xticks` decides where marks appear and `set_xticklabels` decides what they say. Setting labels without setting positions is a common source of labels attached to the wrong ticks, so set both together.

Rotation handles long category names, and is worth avoiding by using horizontal bars instead where possible.

## Formatting numbers

```python
from matplotlib.ticker import FuncFormatter
ax.yaxis.set_major_formatter(FuncFormatter(lambda v, _: f'{v/1000:.0f} kg'))
```

Axis labels reading 3000, 4000, 5000 are correct and make the reader do the conversion. Labels reading 3 kg, 4 kg, 5 kg do not.

The same applies to large numbers generally. An axis in units of ten million is more readable as crores or millions, and the formatter is where that conversion belongs rather than in the data.

## Dates

Matplotlib handles datetime axes automatically, choosing tick intervals appropriate to the range. That works well and can be overridden:

```python
import matplotlib.dates as mdates
ax.xaxis.set_major_locator(mdates.MonthLocator(interval=3))
ax.xaxis.set_major_formatter(mdates.DateFormatter('%b %Y'))
```

The locator decides where ticks fall, the formatter decides how they read. Quarterly ticks labelled by month and year suit a two-year series better than the default, which may give a tick per month and overlapping labels.

This only works when the column is a datetime. A date column left as text is treated as categories, spaced evenly regardless of the actual gaps between them, which quietly misrepresents any irregular series.

> An axis is an argument about what counts as a meaningful difference. Linear says differences matter, log says ratios do, and the default was chosen by a library that knows neither.

## Inverting

```python
ax.invert_yaxis()
```

Occasionally correct, for rankings where first place should sit at the top, or for depth measured downward. Rarely otherwise, and a reader who does not notice the inversion reads the chart backwards.

## Practise the scale choice

Take a right-skewed column, such as city populations or transaction amounts, and plot it on a linear axis.

Most of the values will crowd into the left with a few points stretched far right. Now redraw with `set_xscale('log')`.

The second chart shows structure the first could not. Then check whether the axis is clearly labelled as logarithmic, because without that the second chart is more misleading than the first.
