## Five libraries and the job each one has

Every tutorial you will read starts with the same block of imports and explains none of it.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns
```

Copying that block works. Knowing what each line brings, and which library to reach for when something breaks, is what stops you guessing for the rest of the course.

The important thing is that these are not five alternatives competing for the same job. They are layers, each built on the one below.

## What each one is responsible for

| Library | What it gives you | You reach for it when |
| ---------- | -------------------------------------------------- | ------------------------------------------------ |
| NumPy | Fast arrays of numbers, and arithmetic across them | You need numerical work, or a library hands you arrays |
| pandas | Tables with labelled rows and columns | You have a dataset with named columns |
| Matplotlib | Control over every element of a plot | A chart has to look exactly a certain way |
| Seaborn | Statistical charts in one line, sensibly styled | You want a standard chart of a standard shape |
| Plotly | Charts you can hover, zoom, and filter | The chart is for exploring, or for someone else to poke at |

NumPy sits at the bottom. It stores numbers in a form the machine can work through quickly and applies an operation to a whole array at once instead of looping.

pandas is built on NumPy. It adds what analysis actually needs: column names, row labels, several data types in one table, and missing values that behave sensibly. Load a CSV and you get a pandas object whose numbers are held in NumPy arrays underneath.

Matplotlib is the plotting foundation, able to control every tick and label, and correspondingly wordy. Seaborn sits on top of it, offering common statistical charts in a line or two while still producing Matplotlib objects you can adjust afterwards. Plotly stands slightly apart, producing interactive charts that live in a browser.

> Knowing which layer a problem belongs to is most of the skill in fixing it.

## The layers show up in your error messages

This is not an abstract diagram. It surfaces the moment something goes wrong.

Ask pandas to do arithmetic on a column of text and the error will mention `dtype`, a NumPy idea, because pandas passed the work downwards and NumPy refused it. Adjust a Seaborn chart and you will find yourself calling Matplotlib methods on the object Seaborn returned, because Seaborn built a Matplotlib figure and handed it back.

When an error mentions a library you did not import, you have found the layer below the one you were working in. That is information, not a mystery.

## Why the aliases are always the same

`np`, `pd`, `plt`, `sns`. These are conventions rather than rules, and you should follow them anyway.

Every example you will ever read online uses them, and code written with different aliases is harder for anyone else to help you with. The cost of conforming is zero and the benefit appears every time you paste a snippet from a forum.

Resist collecting libraries. A beginner who imports six things at the top of every notebook because a tutorial did spends time managing tools rather than looking at data. Import what you use. If nothing in your notebook calls `np` directly, that line does not need to be there.

## What else you will hear about

Three more names come up constantly, and it helps to know where they sit so they stop being noise.

| Library | What it is for |
| ------------ | ------------------------------------------------------- |
| SciPy | Scientific computing built on NumPy: statistics, optimisation, signal processing |
| statsmodels | Statistical modelling with detailed output about the fit |
| scikit-learn | Machine learning, with a consistent interface across methods |

All three sit above NumPy in the same way pandas does. You will meet the first when a statistical test is needed and the other two beyond this course. Knowing they exist is enough for now.

## Versions matter more than you expect

Library behaviour changes between versions, and a surprising share of the time an example from the internet does not work as advertised, the reason is a version difference rather than a mistake on your part.

```python
import pandas as pd
pd.__version__
```

Checking that takes two seconds and short-circuits a whole category of confusion. The same attribute works on any of these libraries.

## Check your setup, then stop thinking about it

Run the import block from the top of this page in a fresh notebook. If any line fails, you have found an installation problem now rather than in the middle of an analysis, and the fix is usually one `pip install`.

Then print the version of pandas and one other library, and write both into a markdown cell in the notebook you plan to work in. When something behaves unexpectedly in three weeks, that cell is the first thing worth looking at.

After that, stop thinking about the stack. The layers matter when something breaks. The rest of the time you are loading a file and asking it questions, which is the actual work.
