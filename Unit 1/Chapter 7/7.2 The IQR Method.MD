## Fences built from the middle half of the data

Any rule for flagging unusual values needs a definition of "far from the rest". The interquartile range method builds one from positions rather than distances, which makes it resistant to the very values it is looking for.

## How the fences are built

Sort the data. Find the first quartile $Q_1$, below which a quarter of the values sit, and the third quartile $Q_3$, below which three quarters sit. The interquartile range is the gap between them:

$$\text{IQR} = Q_3 - Q_1$$

Then place fences one and a half interquartile ranges beyond each quartile:

$$\text{lower fence} = Q_1 - 1.5 \times \text{IQR} \qquad \text{upper fence} = Q_3 + 1.5 \times \text{IQR}$$

Anything outside those fences is flagged.

Notice what determines the fences. Only $Q_1$ and $Q_3$, which are positions in the middle of the data. An extreme value at either end has no influence on where the fences sit, so it cannot help hide itself.

## Run on the penguin file

All 342 birds with complete measurements:

| Column | $Q_1$ | $Q_3$ | IQR | Lower fence | Upper fence | Flagged |
| ----------------- | ----: | ----: | ---: | ----------: | ----------: | ------: |
| body_mass_g | 3,550 | 4,750 | 1,200 | 1,750 | 6,550 | 0 |
| bill_length_mm | 39.2 | 48.5 | 9.3 | 25.3 | 62.4 | 0 |
| bill_depth_mm | 15.6 | 18.7 | 3.1 | 10.9 | 23.3 | 0 |
| flipper_length_mm | 190.0 | 213.0 | 23.0 | 155.5 | 247.5 | 0 |

Not one flagged value across four columns and 342 birds. The file is well maintained, and the method has nothing to complain about.

## The result that should make you suspicious

Now run the same method on body mass within each species separately:

| Species | $Q_1$ | $Q_3$ | Fences | Flagged |
| --------- | ----: | ----: | ---------------: | ------: |
| Adelie | 3,350 | 4,000 | 2,375 to 4,975 | 0 |
| Chinstrap | 3,488 | 3,950 | 2,794 to 4,644 | 2 |
| Gentoo | 4,700 | 5,500 | 3,500 to 6,700 | 0 |

Two Chinstrap penguins now stand out: one at 4,800 grams and one at 2,700 grams. Neither was flagged when all three species were pooled.

The reason is the pooled interquartile range. Mixing three species of different sizes produced an IQR of 1,200 grams, which pushed the fences out to 1,750 and 6,550. Almost nothing could fall outside a span that wide. Within Chinstraps alone the IQR is only 462 grams, and the fences tighten accordingly.

> A wide interquartile range can come from real variation or from mixing groups. When it comes from mixing, outlier detection quietly stops working.

## Why 1.5

The multiplier is a convention with a reason behind it. For data that follows a normal distribution, fences at 1.5 interquartile ranges flag roughly 0.7% of observations, which is a workable rate: rare enough to be worth a look, common enough that the method finds something when something is there.

A multiplier of 3 is sometimes used for extreme outliers, flagging far fewer points. Neither number is sacred, and adjusting it is legitimate as long as you say you did.

| Multiplier | Roughly flagged in normal data | Use when |
| ---------- | -----------------------------: | ------------------------------ |
| 1.5 | 0.7% | The default, for a first pass |
| 3.0 | Under 0.001% | Only the most extreme matter |
| 1.0 | About 5% | You want a wide net to inspect |

## Where the method holds up and where it does not

Its strength is resistance. Adding one absurd value to the penguin masses, a 25,000 gram bird, moved the fences from 1,750 and 6,550 only to 1,722 and 6,597. The fences barely noticed, and the value was flagged.

Its weaknesses are worth knowing.

It assumes a single group, as the Chinstrap result showed. Always check within groups when a grouping column exists.

It works on one column at a time, so a value that is unusual only in combination with another column stays invisible.

It flags more than expected on skewed data, because the method's calibration assumes rough symmetry. On income or waiting times, the upper fence will flag a substantial number of legitimate values, and those flags mean "worth a look" rather than "wrong".

And it needs enough data for quartiles to be stable. With a dozen values the quartiles move whenever anything changes, and the fences with them.

## Practise on grouped data

Take a numeric column and a grouping column from any dataset.

Compute the fences for the whole column, count what falls outside, then compute fences within each group and count again.

If the group-level count is higher, you have reproduced the Chinstrap result on your own data, and you have found the reason experienced analysts check for a grouping column before trusting any outlier count.
