## A checklist that runs before any analysis

Outliers are one kind of data problem and not the most common one. Files arrive with missing values, duplicated rows, columns whose type is wrong, categories spelled three ways, and dates that stop halfway through a year.

A quality assessment is a fixed list of checks run on every new dataset, before any question gets asked of it. Having a list matters more than the list being perfect, because the failure mode is not checking the wrong things but forgetting to check at all.

## Six dimensions to check

| Dimension | The question | What failure looks like |
| ------------ | -------------------------------------- | ------------------------------------------ |
| Completeness | Is anything missing? | Blank cells, absent rows, a month with no data |
| Validity | Are values within possible ranges? | Age 200, negative quantity, a mass of 25,000 g |
| Consistency | Do related values agree? | State and pin code from different regions |
| Uniqueness | Is anything recorded twice? | The same order appearing in two rows |
| Timeliness | Does the data cover the period you need? | Records stopping three months ago |
| Accuracy | Do values match reality? | Only checkable against an external source |

The last row is the honest one. Accuracy cannot be assessed from the file alone, because nothing inside a dataset can tell you it disagrees with the world. It requires an external reference or someone who knows.

## Running it on a real file

The Palmer penguin data, assessed against the first five dimensions:

| Check | Result |
| ------------------- | ------------------------------------------------ |
| Rows and columns | 344 rows, 8 columns |
| Missing values | 2 rows with no measurements at all; 11 rows without sex recorded |
| Validity ranges | All masses, bills, and flippers within plausible biological ranges |
| Distinct categories | 3 species, 3 islands, 2 sexes, no spelling variants |
| Duplicates | None |
| Time coverage | Three study seasons, 2007 to 2009 |
| Outlier fences | Nothing flagged on any numeric column when pooled |

That is a clean file, which is why it works so well for teaching and why it misrepresents ordinary working conditions. Most files you receive will fail at least three of these checks.

## The checks worth automating

Six commands answer most of the list, and running them on every new file takes about two minutes.

* Row and column counts, compared against what you were told to expect.
* Count of missing values per column, and the proportion that represents.
* Distinct values for every categorical column, read in full.
* Minimum and maximum for every numeric column, read against what is physically possible.
* Count of duplicated rows, and of duplicated identifiers where identifiers exist.
* Earliest and latest date, and a count per month to reveal gaps.

Reading the distinct values of a categorical column is the one that repays itself fastest. It exposes spelling variants, unexpected categories, stray whitespace, and placeholder codes in a single glance.

## Missingness is not one problem

How much is missing matters less than which rows are missing.

If the 11 penguins without a recorded sex are a random assortment, dropping them costs a little precision and biases nothing. If they were the birds researchers could not approach closely, and those birds differ in some way that matters, then the remaining data describes a different population than the one intended.

The file cannot answer this. What it can do is show whether missing rows differ from complete ones on the columns you do have, which is a useful check: compare the species and island composition of the incomplete rows against the file overall.

> How much data is missing is a fact you can compute. Whether it matters is a question about how the gaps arose, and the answer lives outside the file.

## Writing the assessment down

The output of this work is a short note that travels with the analysis. Six lines is usually enough.

What the file contains and how many rows. Which columns have missing values and how many. What checks failed and what you did about them. What you could not verify. Which rows you excluded and why. And which findings would change if your assumptions about the flawed columns turned out to be wrong.

That note is what lets someone else trust your results, and it is what lets you trust them yourself in three months.

## Practise on the messiest file you can find

Download something from a public portal rather than a teaching repository. Government open data sites are ideal, because their files are real.

Run all six checks and write the assessment note. Count how many of the six dimensions the file fails.

Then compare the experience against working with the penguin file. The difference between the two is the difference between coursework and the job, and meeting it now rather than in your first week of work is the point of the exercise.
