## Saving results so someone else can use them

Analysis produces things worth keeping: a cleaned table, a summary, a filtered subset for a colleague. Writing them out is one method call, with a few decisions attached.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
df.head(3).to_csv('out.csv', index=False)
```

```
species,island,bill_length_mm,bill_depth_mm,flipper_length_mm,body_mass_g,sex,year
Adelie,Torgersen,39.1,18.7,181.0,3750.0,male,2007
Adelie,Torgersen,39.5,17.4,186.0,3800.0,female,2007
Adelie,Torgersen,40.3,18.0,195.0,3250.0,female,2007
```

Clean output: header row, one line per record, nothing extra.

## The index parameter is the one that matters

Leave `index=False` out and pandas writes the index as an unnamed first column.

```python
df.head(2).to_csv('with_index.csv')
```

```
,species,island,bill_length_mm,bill_depth_mm,flipper_length_mm,body_mass_g,sex,year
0,Adelie,Torgersen,39.1,18.7,181.0,3750.0,male,2007
1,Adelie,Torgersen,39.5,17.4,186.0,3800.0,female,2007
```

Note the leading comma on the header line. That is a column with no name, holding 0 and 1, which carry no information.

Read that file back and pandas creates a column called `Unnamed: 0`. Do this a few times and you accumulate `Unnamed: 0`, `Unnamed: 0.1`, and so on, one per round trip.

> Pass `index=False` unless the index holds real information. When it does hold something meaningful, such as a date or an identifier, write it and give it a name.

## Choosing a format

| Format | Method | Good for | Costs |
| ------- | -------------- | ---------------------------------- | --------------------------------- |
| CSV | `to_csv` | Sharing with anyone, any tool | Loses types, large files |
| Excel | `to_excel` | Colleagues who work in spreadsheets | Slow, needs a package, size limits |
| JSON | `to_json` | Feeding an application or API | Verbose, awkward for tables |
| Parquet | `to_parquet` | Reloading in pandas later | Not human readable |

CSV is text, which makes it universal and means types are gone. A date column becomes a string, and reading it back requires `parse_dates` again.

Parquet keeps types, compresses well, and loads far faster. For an intermediate file that only your own code will read, it is the better choice.

## JSON, and the orient parameter

```python
df.head(2).to_json('out.json', orient='records')
```

```
[{"species":"Adelie","island":"Torgersen","bill_length_mm":39.1,...},
 {"species":"Adelie","island":"Torgersen","bill_length_mm":39.5,...}]
```

The `records` orientation writes a list of objects, one per row, which is what most applications and APIs expect. Other orientations arrange the same data by column or by index, and choosing the wrong one produces valid JSON that the receiving system cannot read.

## Excel, when the audience requires it

```python
df.head(3).to_excel('out.xlsx', index=False)
```

This needs `openpyxl` installed. Writing several sheets into one workbook uses a writer object:

```python
with pd.ExcelWriter('report.xlsx') as writer:
    summary.to_excel(writer, sheet_name='Summary', index=False)
    details.to_excel(writer, sheet_name='Detail', index=False)
```

Worth knowing because a great deal of professional output is consumed in Excel, whatever the analysis was done in.

## What writing loses

Two things disappear on the way out to CSV, and both cause trouble later.

Types go. Integers, floats, dates, and categories all become text, and the reader has to infer them again. A column of identifiers with leading zeros survives the write and loses its zeros on the next read.

Missing values become ambiguous. `NaN` is written as an empty field by default, which reads back correctly, and a text column containing the word "NA" is indistinguishable from a missing value unless you control both ends.

The `na_rep` parameter lets you write something explicit if the receiving system needs it.

## Before you write anything

Three checks take ten seconds and prevent the most common problems.

Confirm the shape is what you expect, since writing a filtered table when you meant the whole one is easy and silent. Confirm the columns are the ones you intend to share, because analysis files often accumulate working columns nobody else needs. And decide whether the index is meaningful.

## Practise the round trip

Take a DataFrame with a date column and a numeric column, write it to CSV, read it back, and compare `dtypes` before and after.

The date will have become text. Then repeat with Parquet and compare again.

That comparison is the clearest argument for choosing a format deliberately, and it explains why intermediate files in professional pipelines are rarely CSVs.
