## Choosing which columns to work with

A file with forty columns is unwieldy. Most questions need four of them, and pulling out the ones you want is the operation you will perform most often in pandas.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
```

## One column, two ways

```python
df['species']            # a Series
df[['species']]          # a DataFrame with one column
```

Same values, different containers. The shapes differ, (344,) against (344, 1), and so do the available methods.

The inner brackets in the second form are a list. `df[['species', 'body_mass_g']]` passes a list of two names, and once you read it that way the double brackets stop looking strange.

```python
df[['species', 'body_mass_g']].head(3)
```

```
  species  body_mass_g
0  Adelie       3750.0
1  Adelie       3800.0
2  Adelie       3250.0
```

## Which one to reach for

| You want | Use | Because |
| ------------------------------- | ------------------- | -------------------------------------- |
| To compute on one column | `df['col']` | Series methods like `value_counts()` |
| A table with a subset of columns | `df[['a', 'b']]` | Keeps the DataFrame structure |
| To create a new column | `df['new'] = ...` | Assignment needs single brackets |
| To pass columns onward | Either | Depends on what receives it |

The order in your list is the order you get, so selection doubles as reordering. `df[['sex', 'species']]` puts sex first.

## Attribute access and why to skip it

`df.species` returns the same Series and is tempting. It breaks in three cases: column names containing spaces or punctuation, names that collide with a DataFrame method such as `count`, `min`, or `shape`, and any attempt to create a new column.

```python
df['mass_kg'] = df['body_mass_g'] / 1000     # creates the column
df.mass_kg = df['body_mass_g'] / 1000        # does not
```

The second line runs without error and silently fails to add a column. Use brackets throughout and the inconsistency never arises.

## Selecting by type

```python
df.select_dtypes(include='number')
df.select_dtypes(exclude='number')
```

Useful when you want every numeric column without naming them, which comes up whenever you compute summaries across a wide table.

On the penguin file the first returns the four measurements plus `year`, and the second returns species, island, and sex. The `year` column landing among the numbers is a reminder that a stored type is not the same as a meaningful one.

## Selecting by name pattern

```python
df.filter(like='bill')          # columns whose name contains 'bill'
df.filter(regex='_mm$')         # columns whose name ends in _mm
```

Files with systematic naming, such as `sales_2021`, `sales_2022`, `sales_2023`, make this far quicker than typing every name.

## Dropping instead of keeping

```python
df.drop(columns=['year'])
```

When you want most columns, naming the few to remove is shorter and clearer than listing the rest.

Note that this returns a new DataFrame and leaves the original alone. Assign the result or nothing changes:

```python
df = df.drop(columns=['year'])
```

Older code uses `inplace=True` for this. It is falling out of favour, it saves no memory in practice, and it makes chaining impossible. Prefer assignment.

## Renaming

```python
df.rename(columns={'body_mass_g': 'mass_g'})
```

A dictionary of old name to new name. Only the columns you mention change.

For a systematic clean-up, operating on the whole set at once is faster:

```python
df.columns = df.columns.str.lower().str.replace(' ', '_')
```

That one line lowercases every name and replaces spaces with underscores, which handles most of what is wrong with column names in files exported from spreadsheets.

> Fix column names immediately after loading, before writing any analysis. Every line you write against a name like `Total Sales (₹)` is a line you rewrite when you clean it later.

## Creating columns

```python
df['mass_kg'] = df['body_mass_g'] / 1000
df['is_large'] = df['body_mass_g'] > 5000
```

Assignment to a name that does not exist creates the column, and it lands at the end. The right-hand side is computed for every row at once, with no loop.

## Practise on a wide file

Find a dataset with at least fifteen columns.

Select five by name, then the same five with `filter`, then everything except three using `drop`. Clean the column names with the one-line lowercase and underscore transformation.

Then check `select_dtypes(include='number')` and see whether every column it returns is actually a quantity. Identifiers and year columns hiding among the numbers is the normal result, and knowing they are there prevents a meaningless summary later.
