## Keeping the rows that meet a condition

Filtering is how a question narrows to the rows that can answer it. Which penguins weigh over five kilograms, which students fell below the attendance threshold, which orders came from one city.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

big = df[df['body_mass_g'] > 5000]
len(big)                      # 61
big['species'].unique()       # ['Gentoo']
```

Sixty-one birds weigh more than five kilograms, and every one of them is a Gentoo. A filter and one follow-up line, and a fact about the file emerges.

## What is happening inside the brackets

`df['body_mass_g'] > 5000` produces a Series of True and False, one per row. Passing that Series into `df[...]` keeps the rows where it is True.

Separating the two steps makes everything else obvious, and it is worth writing the mask to its own variable when a condition gets complicated:

```python
heavy = df['body_mass_g'] > 5000
heavy.sum()        # 61, how many rows the filter will keep
df[heavy]
```

Checking `mask.sum()` before filtering is a habit worth forming. A filter you expected to keep most of the data returning four rows means the condition is wrong, and catching that immediately is far easier than debugging it three steps later.

## Combining conditions

```python
df[(df['body_mass_g'] > 5000) & (df['sex'] == 'female')]      # 5 rows
```

Use `&` for and, `|` for or, `~` for not, and wrap each condition in its own parentheses. The Python keywords `and`, `or`, and `not` raise a ValueError about ambiguous truth values, because they try to reduce a whole Series to a single boolean.

The parentheses are not optional. These operators bind more tightly than the comparisons, so leaving them out produces an error that does not obviously point at the cause.

## Methods that replace clumsy conditions

| Method | Instead of |
| ------------------------- | ------------------------------------------ |
| `.isin(['Dream', 'Torgersen'])` | Chaining several `\|` comparisons |
| `.between(3000, 4000)` | `(col >= 3000) & (col <= 4000)` |
| `.isna()`, `.notna()` | Testing for missing values |
| `.str.startswith('A')` | Manual string handling |
| `.str.contains('mm')` | Manual string handling |

```python
len(df[df['island'].isin(['Dream', 'Torgersen'])])     # 176
len(df[df['body_mass_g'].between(3000, 4000)])         # 161
len(df[df['body_mass_g'].notna()])                     # 342
```

`isin` is the one you will use most. Filtering to a list of cities, departments, or product codes is a single readable call instead of a chain of comparisons.

The `.str` accessor gives every string method, applied element-wise. It skips missing values rather than failing on them, which is convenient and means the result can contain `NaN` where the original was missing.

## query, for readability

```python
df.query('body_mass_g > 5000 and sex == "female"')      # 5 rows
```

The condition is written as a string, and inside it the plain English keywords work and column names need no `df[...]` wrapper.

For long conditions this is considerably easier to read. The cost is that the column names are inside a string, so your editor cannot check them, and names with spaces need backticks.

## Missing values and filters

A comparison against a missing value returns False, so rows with `NaN` are silently excluded from both `col > 5000` and `col <= 5000`.

```python
len(df[df['body_mass_g'] > 5000]) + len(df[df['body_mass_g'] <= 5000])     # 342, not 344
```

Two rows have no recorded mass and appear in neither result. Nothing warns you, and if you are counting proportions, your denominator has quietly changed.

> Two complementary filters do not always cover the whole table. When missing values are present, the rows with gaps fall through both.

## Assigning to filtered rows

```python
df.loc[df['body_mass_g'] > 5000, 'size_class'] = 'large'
```

Do the row selection and the column selection in one `loc` call. Filtering first and then assigning to a column of the result operates on an intermediate object and may not reach the original DataFrame.

## Practise the counting habit

Take any dataset and write four filters of increasing complexity, checking `mask.sum()` before applying each.

Then write two complementary conditions, count both results, and check whether they add up to the row count. Where they do not, find the rows that fall through and confirm they are the ones with missing values.

That check takes one line and it is the difference between a proportion you can defend and one that is quietly wrong.
