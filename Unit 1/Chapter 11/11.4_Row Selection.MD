## Two selectors, and why both exist

Columns are selected by name. Rows have both a label, which is the index, and a position, which is where they sit in the table. pandas gives you one selector for each.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
```

`loc` selects by label. `iloc` selects by position. On a freshly loaded file the two look identical, because the index is 0, 1, 2, and so on, and every label happens to equal its position.

They stop agreeing the moment you sort or filter, and that is when the distinction starts to matter.

## The basic forms

```python
df.loc[0:2, ['species', 'body_mass_g']]
```

```
  species  body_mass_g
0  Adelie       3750.0
1  Adelie       3800.0
2  Adelie       3250.0
```

```python
df.iloc[0:2, [0, 5]]
```

```
  species  body_mass_g
0  Adelie       3750.0
1  Adelie       3800.0
```

Both take rows first, then columns, separated by a comma. `loc` names things; `iloc` counts them.

## The endpoint difference

```python
len(df.loc[0:2])     # 3
len(df.iloc[0:2])    # 2
```

`loc` includes its endpoint. `iloc` excludes it, following ordinary Python slicing.

That inconsistency is deliberate. Labels are names rather than positions, and asking for everything from label 0 to label 2 naturally includes label 2. It still catches people, and an off-by-one in a slice is exactly the kind of error that produces plausible wrong output.

| | `loc` | `iloc` |
| ------------------- | ------------------ | -------------------- |
| Selects by | Label | Position |
| Slice endpoint | Included | Excluded |
| Columns specified as | Names | Positions |
| Accepts a boolean mask | Yes | No |
| Works after sorting | Follows the labels | Follows the new order |

## Where they diverge

```python
d2 = df.sort_values('body_mass_g').head(5)
d2[['species', 'body_mass_g']]
```

```
       species  body_mass_g
314  Chinstrap       2700.0
58      Adelie       2850.0
64      Adelie       2850.0
54      Adelie       2900.0
98      Adelie       2900.0
```

Sorting rearranged the rows and carried the original index labels along. The first row is now labelled 314.

`d2.iloc[0]` returns that first row, the 2,700 gram Chinstrap. `d2.loc[0]` looks for the row labelled 0, which is not in this subset at all and raises an error.

This is why the two selectors exist. After any sort or filter, position and label are different questions, and you have to know which you are asking.

## A meaningful index makes loc useful

```python
s = df.set_index('species')
s.loc['Gentoo']        # 124 rows
```

With species as the index, `loc` retrieves every Gentoo row by name. The index does not have to be unique, and when it is not, `loc` returns all matching rows.

This is where labels earn their place: dates, station codes, student IDs, product codes. Looking up by the thing itself rather than by a position you had to compute.

## Selecting rows and columns together

```python
df.loc[0:2, 'species':'bill_length_mm']     # a range of columns by name
df.loc[:, 'species']                        # every row, one column
df.iloc[-3:, :]                             # last three rows, all columns
```

The colon means everything along that dimension. Column slicing by name works in `loc` and follows the column order in the file, which makes it dependent on that order and therefore a little fragile.

> When you mean position, write `iloc`. When you mean label, write `loc`. Bare `df[...]` does different things depending on what you pass, and being explicit costs four characters.

## The chained indexing problem

```python
df[df['species'] == 'Gentoo']['body_mass_g'] = 0     # unreliable
df.loc[df['species'] == 'Gentoo', 'body_mass_g'] = 0  # correct
```

The first line selects rows, then selects a column from that result, then assigns. Whether the assignment reaches the original DataFrame depends on whether the intermediate was a view or a copy, which is not something you can tell by looking.

Older pandas warned about this with a `SettingWithCopyWarning`. Newer versions have changed the underlying behaviour so that the first form reliably does not modify the original.

The rule is simple: when assigning, do the row and column selection in one `loc` call.

## Practise the divergence

Load any file, sort it by a numeric column, and take the first five rows.

Print `iloc[0]` and then try `loc[0]`. One returns a row and one probably raises a KeyError.

Then use `reset_index(drop=True)` and try both again. They now agree, because you replaced the labels with positions. Producing the error deliberately once is what makes the distinction stick.
