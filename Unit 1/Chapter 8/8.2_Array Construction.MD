## Six ways to make an array, and when each fits

Every NumPy session starts by getting data into an array. Sometimes it comes from a file, and often you need to build one directly: a grid of zeros to fill in, a sequence of test values, an identity matrix.

```python
import numpy as np
```

That import line, with that alias, is universal. Follow it.

## From data you already have

`np.array()` converts a Python list, or a list of lists, into an array.

```python
a = np.array([[1, 2, 3], [4, 5, 6]])
```

```
[[1 2 3]
 [4 5 6]]
```

The nesting decides the shape. A flat list gives a one-dimensional array; a list of equal-length lists gives a two-dimensional one with a row per inner list.

The types get unified on the way in. A list mixing integers and floats produces an array of floats, because every element must share one type.

## Arrays you fill in later

Three constructors make an array of a given shape without meaningful contents.

```python
np.zeros(3)          # [0. 0. 0.]
np.ones((2, 3))      # a 2x3 array of 1.0
np.full((2, 2), 7)   # a 2x2 array of 7
```

Note the shape argument. For more than one dimension it is a tuple, so `np.ones((2, 3))` and not `np.ones(2, 3)`.

Note also the decimal points. `np.zeros` and `np.ones` produce floats by default, while `np.full` takes its type from the value you give it. If you need integer zeros, say so with `np.zeros(3, dtype=int)`.

## Sequences

Two constructors generate evenly spaced values, and the difference between them causes constant confusion.

```python
np.arange(0, 10, 2)     # [0 2 4 6 8]
np.linspace(0, 1, 5)    # [0.   0.25 0.5  0.75 1.  ]
```

`arange` takes a step size and excludes the endpoint. `linspace` takes a count and includes both endpoints.

| | `arange(start, stop, step)` | `linspace(start, stop, num)` |
| --------------- | --------------------------- | ---------------------------- |
| Third argument | The gap between values | How many values you want |
| Endpoint | Excluded | Included by default |
| Number of values | Depends on the arithmetic | Exactly what you asked for |
| Use when | You know the spacing | You know how many points you need |

> Use `linspace` whenever the endpoint matters or the step would be fractional. Floating point arithmetic makes `arange` with a decimal step unreliable about whether the last value appears.

## Special-purpose constructors

```python
np.eye(3)
```

```
[[1. 0. 0.]
 [0. 1. 0.]
 [0. 0. 1.]]
```

An identity matrix: ones on the diagonal, zeros elsewhere. It appears constantly in linear algebra and rarely in ordinary data work.

## Random values, reproducibly

```python
rng = np.random.default_rng(0)
rng.random(3)          # [0.637  0.2698 0.041 ]
```

The number passed to `default_rng` is the seed. The same seed always produces the same sequence, which is what makes an analysis involving randomness reproducible.

Always set a seed when randomness enters your work. An unseeded simulation gives different answers each run, and neither you nor anyone else can check the result.

## Choosing a constructor

| You have | You want | Use |
| ---------------------------- | -------------------------- | ------------------ |
| A Python list | An array of it | `np.array()` |
| Nothing yet, a known shape | A container to fill | `np.zeros()` or `np.ones()` |
| A start, stop, and step | A sequence | `np.arange()` |
| A start, stop, and count | Evenly spaced points | `np.linspace()` |
| A shape and a constant | Every element the same | `np.full()` |
| A shape and randomness | Test or simulated data | `default_rng().random()` |

## A note on growing arrays

There is no efficient append. Adding an element to an array allocates a new block and copies everything across, so building an array in a loop is slower than building a list and converting once at the end.

```python
# avoid this
result = np.array([])
for x in values:
    result = np.append(result, x * 2)

# prefer this
result = np.array([x * 2 for x in values])
```

Better still, if the operation vectorises, skip the loop altogether.

## Practise the two sequence functions

Produce the values 0, 0.1, 0.2, up to 1.0 twice: once with `arange` and once with `linspace`.

Count how many values each returns and check whether 1.0 appears in both. The discrepancy you find is not a bug, and understanding why it happens is the reason `linspace` exists.
