## Four properties that answer most of your questions

An array carries information about itself, and reading it is the first thing to do when something behaves unexpectedly.

```python
import numpy as np
a = np.array([[1, 2, 3], [4, 5, 6]])
```

```
a.shape      (2, 3)
a.ndim       2
a.dtype      int64
a.size       6
a.itemsize   8
a.nbytes     48
```

Six attributes, no parentheses, since these are properties rather than methods.

## What each one tells you

| Attribute | Meaning | Why you check it |
| ---------- | ---------------------------------------- | -------------------------------------------- |
| `shape` | Length along each dimension, as a tuple | Almost every error involves a shape mismatch |
| `ndim` | How many dimensions | Whether this is a row, a table, or a stack |
| `dtype` | The type shared by every element | Silent truncation and precision surprises |
| `size` | Total number of elements | Sanity-checking a reshape or a filter |
| `itemsize` | Bytes per element | Understanding memory use |
| `nbytes` | Total bytes, `size` times `itemsize` | Whether a file will fit in memory |

`shape` and `dtype` earn their keep daily. The others are occasional.

## Shape is a tuple, and its length is ndim

```python
np.zeros(3).shape        # (3,)
np.zeros((3, 1)).shape   # (3, 1)
np.zeros((1, 3)).shape   # (1, 3)
```

Three arrays holding three zeros, with three different shapes.

The first is one-dimensional. The second is a column: two dimensions, three rows, one column. The third is a row: two dimensions, one row, three columns.

They behave differently in arithmetic, in matrix multiplication, and in anything that combines arrays. The trailing comma in `(3,)` is Python's way of writing a one-element tuple, and it is the visible sign that you have a flat array rather than a two-dimensional one.

> When an operation fails or gives a surprising result, print the shapes first. In most cases the answer is there.

## dtype, and the mistakes it causes

Every element shares one type, chosen when the array is created and rarely mentioned afterwards.

```python
a = np.array([1, 2, 3])
a.dtype           # int64
(a / 2).dtype     # float64
a + 0.5           # [1.5 2.5 3.5]
```

Dividing integers produces floats, and NumPy promotes the type automatically. That is the well-behaved case.

The badly behaved case is assignment into an array whose type is too small:

```python
x = np.array([1, 2, 3], dtype=np.int8)
x[0] = 200        # OverflowError
```

An 8-bit integer holds values from −128 to 127, so 200 does not fit. Recent NumPy versions raise an error here, which is a considerable improvement on older behaviour where the value silently wrapped around to a negative number.

Silent truncation still happens in the other direction:

```python
y = np.array([1, 2, 3])      # int64
y[0] = 3.7                   # stored as 3
```

The decimal part is discarded without a warning, because the array's type is integer and NumPy converts on the way in.

## Choosing a dtype deliberately

Most of the time the default is right. Two situations justify choosing.

Memory pressure is the first. An array of a hundred million small integers takes 800 MB as `int64` and 100 MB as `int8`. On a large file that difference decides whether the work is possible.

Precision is the second. `float32` uses half the memory of `float64` and carries about seven significant digits instead of sixteen. For most measurements that is plenty; for accumulating millions of values it is not, because rounding errors compound.

| dtype | Bytes | Range or precision |
| --------- | ----: | -------------------------------- |
| `int8` | 1 | −128 to 127 |
| `int32` | 4 | About ±2.1 billion |
| `int64` | 8 | The default for integers |
| `float32` | 4 | About 7 significant digits |
| `float64` | 8 | About 16 significant digits, the default |
| `bool` | 1 | True or False |

## What this explains later

Both attributes surface constantly in pandas.

A column that will not do arithmetic usually has an `object` dtype, meaning it holds Python objects rather than numbers, typically because one row contained text. A DataFrame that consumes far more memory than the file it came from usually holds several `object` columns. And an error mentioning shapes when you were working with a table is NumPy speaking from underneath.

## Practise reading before guessing

Create three arrays with shapes `(4,)`, `(4, 1)`, and `(1, 4)`, all holding the same four numbers.

Print the shape and ndim of each. Then add the first to the second and print the shape of the result.

The answer will probably not be what you expect, and working out why is the natural entry point to the broadcasting rules that come next.
