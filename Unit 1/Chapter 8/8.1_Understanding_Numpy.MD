## The same calculation, twenty times faster

Take a million numbers and double each one. In plain Python you write a loop or a comprehension:

```python
lst = list(range(1_000_000))
doubled = [x * 2 for x in lst]
```

In NumPy you write the operation once and apply it to the whole array:

```python
import numpy as np
arr = np.arange(1_000_000)
doubled = arr * 2
```

Timed on the same machine, the first takes about 40 milliseconds and the second about 2.2. Summing the same million values takes 8.6 milliseconds with Python's `sum` and 0.7 with `arr.sum()`.

```
double:  list   40.4 ms | numpy    2.2 ms | 19x
sum:     list    8.6 ms | numpy    0.7 ms | 12x
```

Those ratios hold roughly across most numerical work, and they are the reason every data library in Python is built on NumPy rather than on lists.

## Why a list is slow

A Python list is a list of pointers. Each element points somewhere else in memory, and each of those places holds a full Python object carrying its type, its reference count, and its value.

Doubling one element means following a pointer, checking what type the object is, finding the right multiplication routine, allocating a new object for the result, and storing another pointer. That work happens a million times.

A NumPy array stores the numbers themselves, packed end to end in one block of memory, all of the same type. Doubling the array runs one tight loop in compiled C over that block, with no per-element type checking and no object creation.

| | Python list | NumPy array |
| ---------------- | ---------------------------------- | ----------------------------- |
| What it holds | Pointers to separate objects | The values themselves, packed together |
| Types | Any mixture | One type for the whole array |
| Per element cost | Type check, dispatch, allocation | None |
| Loop runs in | Python | Compiled C |
| Size for a million integers | About 36 MB | 8 MB |

The memory figures matter as much as the speed. The same million integers occupy roughly 36 MB as a list and exactly 8 MB as an array of 64-bit integers, because the array carries no object overhead.

## Vectorisation

Writing `arr * 2` instead of a loop is called vectorisation. The loop still happens; it happens inside compiled code rather than in the interpreter.

This changes how you write, not just how fast it runs. The NumPy version says what you want done to the data. The loop version says how to walk through it.

```python
# Python thinking
result = []
for x in values:
    if x > 100:
        result.append(x * 2)

# NumPy thinking
result = values[values > 100] * 2
```

The second is shorter, faster, and closer to the sentence you would say out loud. Almost every operation you would reach for a loop to perform has a vectorised form, and finding it is most of what learning NumPy consists of.

> If you are writing a `for` loop over a NumPy array, there is usually a way not to. The loop is not wrong; it is slow and longer than the alternative.

## What you give up

Two things, and both are deliberate trades.

Arrays hold one type. You cannot mix numbers and text in a single array, or rather you can, and NumPy will convert everything to a common type and lose the efficiency that made it worth using. Mixed types are what pandas exists for.

Arrays are fixed in size. Appending to an array copies the whole thing, so the list habit of building up results one element at a time is a mistake here. Create the array at its final size, or build a list and convert once at the end.

## Where it sits in your work

You will rarely use NumPy directly for a whole analysis. You will use pandas, which stores its numbers in NumPy arrays and hands the arithmetic down to them.

That layering is why this comes first. Understanding arrays, their types, and their shapes explains error messages you will meet in pandas, and explains why some operations on a table are instant while others take a minute.

## See the difference yourself

Run both versions on your own machine:

```python
import numpy as np, timeit
setup = "import numpy as np; lst=list(range(1_000_000)); arr=np.arange(1_000_000)"
print(min(timeit.repeat("[x*2 for x in lst]", setup=setup, repeat=5, number=1)))
print(min(timeit.repeat("arr*2", setup=setup, repeat=5, number=1)))
```

Then raise the size to ten million and run it again. The ratio stays roughly constant while both times grow, which tells you the advantage is a property of how the work is done rather than an artefact of this particular size.
