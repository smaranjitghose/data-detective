## What arrays cannot hold

The penguin file has eight columns. Three hold text, four hold decimal measurements, one holds a year. Two rows are missing every measurement, and eleven more are missing sex.

Try to put that in a NumPy array and the trouble starts immediately. An array holds one type, so text and numbers cannot coexist without converting everything to text and losing the arithmetic. Columns have positions but no names, so you refer to `data[:, 3]` and hope you counted right. And missing values have no natural representation among integers.

pandas exists for exactly this shape of data, which is the shape almost all real data has.

## What it adds

| Need | NumPy | pandas |
| ---------------------------- | ------------------------- | ------------------------------ |
| Different types per column | One type for everything | One type per column |
| Refer to columns by name | Position only | `df['body_mass_g']` |
| Row labels | Position only | An index, which can be anything |
| Missing values | Awkward for integers | Built in, and handled by every operation |
| Read a CSV or Excel file | Manual work | One function call |
| Group and summarise | Manual work | One method call |

Nothing in that table replaces NumPy. pandas stores its numeric columns as NumPy arrays and hands the arithmetic to them, so the speed you read about in the previous unit is the speed you get here.

> pandas is a layer of labels, types, and missing-value handling over NumPy arrays. Understanding what sits underneath explains most of its error messages.

## Two structures

A Series is one column: a sequence of values with an index attached.

A DataFrame is a table: several Series sharing one index, each with a name and its own type.

Everything else in pandas is built from those two. Selecting a column from a DataFrame gives a Series. Selecting several gives a smaller DataFrame. Summarising a DataFrame column by column gives a Series with the column names as its index.

## Loading a file is one line

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
df.shape
```

```
(344, 8)
```

That single call opened the file, split it on commas, read the header row into column names, inferred a type for every column, and represented the empty fields as missing values.

Doing the same work with Python's built-in file handling takes twenty lines and gets the types wrong.

## Types are inferred per column

```python
df.dtypes
```

```
species                  str
island                   str
bill_length_mm       float64
bill_depth_mm        float64
flipper_length_mm    float64
body_mass_g          float64
sex                      str
year                   int64
```

Four columns of decimals, one of integers, three of text. Each column is stored appropriately, and each supports the operations that suit it.

One thing to know before you compare this against your own screen. Recent pandas versions report text columns as `str`, while pandas 2 and earlier report them as `object`. The meaning is the same, and a great deal of older material online uses the `object` label.

The measurement columns are `float64` rather than integers even though body mass is recorded in whole grams. That is because two rows are missing, and older pandas represents a missing number as a special float value. Integer columns with gaps therefore become float columns, which surprises people the first time.

## What pandas is not for

Two limits worth knowing at the start.

It works in memory. A file larger than your available RAM will not load, and the practical ceiling on an ordinary laptop is a few gigabytes, well before that limit.

And it is not a database. For data that many people query at once, that needs to be updated safely, or that runs to hundreds of millions of rows, a database is the right tool and pandas is what you use on the results it returns.

## Load something of your own

Find a CSV you care about, load it with `read_csv`, and print its shape and dtypes.

Check two things. Does the row count match what you expected from the file, and did every column get the type you would have chosen?

Columns that came out as text when you expected numbers are the most common surprise, and the reason is always a stray value somewhere in the column. Finding it is the first piece of real data work in this course.
