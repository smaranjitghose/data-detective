## A column that knows its own labels

A Series is one column of data with an index attached to it. Take any column out of a table and that is what you get.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
s = df['body_mass_g']
s.head()
```

```
0    3750.0
1    3800.0
2    3250.0
3       NaN
4    3450.0
Name: body_mass_g, dtype: float64
```

Four things are visible. The values on the right. The index on the left. The name of the Series. And its dtype, shared by every value.

## Building one directly

```python
s2 = pd.Series([3750, 3800, 3250], index=['a', 'b', 'c'], name='mass')
```

```
a    3750
b    3800
c    3250
Name: mass, dtype: int64
```

The index does not have to be numbers. It can be labels, dates, or names, and that flexibility is a large part of what pandas offers over an array.

When you do not supply an index, you get positions: 0, 1, 2, and so on, which is what the penguin column has.

## Two ways to reach a value

```python
s2['b']        # 3800, by label
s2.iloc[1]     # 3800, by position
```

Both return the same value here because 'b' is the second label. When the index is itself made of numbers, the two diverge sharply, and mixing them up is a source of quiet errors.

The habit worth forming now: use `.iloc` when you mean position and a plain label lookup when you mean label. Being explicit costs three characters.

## Operations apply to every value

```python
s2 * 2
```

```
a    7500
b    7600
c    6500
Name: mass, dtype: int64
```

The arithmetic is vectorised exactly as in NumPy, because the values are held in a NumPy array underneath. The index comes along unchanged, which is the addition pandas makes.

Comparisons work the same way and produce a Series of booleans, which is what filtering uses.

## The index does real work

This is where a Series stops being an array with decoration.

```python
x = pd.Series([1, 2, 3], index=['a', 'b', 'c'])
y = pd.Series([10, 20, 30], index=['b', 'c', 'd'])
x + y
```

```
a     NaN
b    12.0
c    23.0
d     NaN
dtype: float64
```

pandas matched the two Series by label, not by position. Where both had a label, it added the values. Where only one did, the result is missing.

Two arrays would have added position by position and given three numbers. pandas gave four, and the two `NaN` entries are telling you the inputs did not cover the same set of labels.

> Alignment by label is either the most useful behaviour in pandas or the most confusing, depending on whether you know it is happening.

The useful side: combining measurements from two sources that overlap partially does the right thing automatically. The confusing side: an arithmetic result full of unexpected `NaN` values almost always means two indexes that do not match.

## Missing values are part of the design

The penguin mass column has two missing entries, shown as `NaN`.

Every summary method skips them by default. `s.mean()` averages the 342 recorded values, and `s.count()` returns 342 rather than 344. That is usually what you want, and it is a decision being made for you, so it is worth knowing which methods make it.

`s.isna().sum()` counts them, and it is the first thing to run on any unfamiliar column.

## Useful methods on a single column

| Method | Returns |
| ------------------ | ---------------------------------------- |
| `head()`, `tail()` | The first or last few entries |
| `value_counts()` | How often each distinct value occurs |
| `unique()`, `nunique()` | The distinct values, or how many |
| `isna().sum()` | Count of missing entries |
| `describe()` | Count, mean, spread, and quartiles |
| `sort_values()` | The Series in order, index carried along |

`value_counts()` is the one you will use most on text columns, and it is how you find spelling variants and unexpected categories in a single glance.

## Practise the alignment

Build two small Series with partly overlapping indexes, as in the example above, and add them.

Then reset one of them with `.reset_index(drop=True)` and add again. The second result will differ, because you replaced the labels with positions and the alignment now matches everything up.

Producing both outcomes deliberately, once, is what stops an unexpected column of `NaN` from being a mystery later.
