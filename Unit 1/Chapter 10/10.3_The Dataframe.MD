## Several columns sharing one index

A DataFrame is a table: a collection of Series that all share the same index, each with a name and its own type.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
df.head(3)
```

```
  species     island  bill_length_mm  bill_depth_mm  flipper_length_mm  body_mass_g     sex  year
0  Adelie  Torgersen            39.1           18.7              181.0       3750.0    male  2007
1  Adelie  Torgersen            39.5           17.4              186.0       3800.0  female  2007
2  Adelie  Torgersen            40.3           18.0              195.0       3250.0  female  2007
```

Down the left is the index, shared by every column. Across the top are the column names. Each column holds one type.

## Its three parts

```python
df.shape       # (344, 8)
df.columns     # the eight column names
df.index       # RangeIndex from 0 to 343
```

Rows and columns are not symmetric in pandas, and this is worth absorbing early. Columns have names and types and are the natural unit of work. Rows are records, usually addressed by position or by a filter rather than by name.

That asymmetry shapes everything. Operations are applied to columns; rows are what you select.

## Selecting a column

```python
df['species']            # a Series
df[['species']]          # a DataFrame with one column
df[['species', 'body_mass_g']]
```

```
  species  body_mass_g
0  Adelie       3750.0
1  Adelie       3800.0
2  Adelie       3250.0
```

One set of brackets with a single name gives a Series of shape (344,). Two sets of brackets give a DataFrame of shape (344, 1), even though it holds the same values.

| What you write | What you get | Shape |
| ------------------------- | ------------ | -------- |
| `df['species']` | Series | (344,) |
| `df[['species']]` | DataFrame | (344, 1) |
| `df[['species', 'sex']]` | DataFrame | (344, 2) |

The inner brackets are a list of column names. Once you see it that way, the double-bracket syntax stops looking like a quirk.

Which one you want depends on what comes next. Series have methods DataFrames do not, such as `value_counts()`, and DataFrames have methods Series do not.

## Attribute access, and why to avoid it

`df.species` also works and returns the same Series. It is shorter and it fails in three situations: column names with spaces, names that clash with an existing method such as `count` or `shape`, and creating a new column.

```python
df['mass_kg'] = df['body_mass_g'] / 1000     # works
df.mass_kg = df['body_mass_g'] / 1000        # silently does not create a column
```

Use brackets. The consistency is worth more than the four saved characters.

## Types belong to columns, not to the table

```python
df.dtypes
```

```
species                  str
island                   str
bill_length_mm       float64
body_mass_g          float64
year                   int64
```

This is the central difference from a NumPy array. Each column is internally a NumPy array of one type, and the DataFrame holds them together with a shared index.

A column showing `object` in pandas 2, or `str` in pandas 3, holds text. A numeric column that unexpectedly shows one of those labels contains something non-numeric, usually a stray value, and no arithmetic will work on it until that is found.

## The index does the same work as in a Series

Every operation combining two DataFrames aligns them by index first. Merging, concatenating, and arithmetic all match rows by label rather than by position.

The penguin file has a default index of 0 to 343, which carries no meaning. Any column with unique values can become the index instead:

```python
df.set_index('species')      # now the index is the species name
df.reset_index()             # back to positions
```

Setting a meaningful index makes label-based lookup natural and makes alignment across files automatic. It is optional, and worth doing when rows have a genuine identifier.

> A DataFrame is a dictionary of Series with a shared index. Almost every behaviour that surprises you follows from that sentence.

## What a DataFrame is not

It is not a spreadsheet, in one important respect: there are no formulas linking cells. A column computed from another is computed once, and changing the source afterwards does not update it.

And it is not ordered by anything meaningful unless you sort it. The order rows arrive in is the order the file had, which often encodes something, but nothing enforces it.

Load any CSV and print `shape`, `columns`, `dtypes`, and `index`.

Then select one column two ways, with single and double brackets, and print the type and shape of each result.

Then create a new column from an existing one using bracket assignment. Confirm it appears in `df.columns` and that `shape` has grown by one. Three minutes, and the structure stops being abstract.
