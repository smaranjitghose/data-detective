## Four ways in, and one you will use most

Most of the time a DataFrame comes from a file. Sometimes you build one directly: to hold a summary you computed, to construct a small example, or to convert something a library handed back.

## From a dictionary

The most readable route. Keys become column names, values become columns.

```python
import pandas as pd
d = pd.DataFrame({'species': ['Adelie', 'Gentoo'],
                  'mass': [3750, 5000]})
```

```
  species  mass
0  Adelie  3750
1  Gentoo  5000
```

```python
d.dtypes
```

```
species      str
mass       int64
```

Every list must be the same length. Types are inferred per column, which is why `mass` came out as integers and `species` as text.

This is the form to use when your data is naturally organised by column, which is how you usually think about a small table you are constructing.

## From a list of dictionaries

```python
pd.DataFrame([{'a': 1, 'b': 2}, {'a': 3, 'b': 4}])
```

```
   a  b
0  1  2
1  3  4
```

Each dictionary is a row. This suits data arriving record by record, which is the shape of most API responses and JSON files.

Missing keys are handled gracefully: a dictionary lacking a key gets `NaN` in that column, and the column set is the union of all keys.

## From a NumPy array

```python
import numpy as np
pd.DataFrame(np.arange(6).reshape(2, 3), columns=['x', 'y', 'z'])
```

```
   x  y  z
0  0  1  2
1  3  4  5
```

The array supplies the values and the shape; you supply the column names. Without `columns` you get integer names, which works and reads badly.

This is the route back from computations done in NumPy, and it only fits when every column shares one type, since the array does.

## From a file

```python
df = pd.read_csv('penguins.csv')
```

The one you will use most, and the subject of a later topic in its own right. `read_csv` has a large number of parameters for handling the ways real files misbehave, and the default call is enough for well-formed ones.

Similar functions exist for other formats: `read_excel`, `read_json`, `read_parquet`, and `read_sql`.

## Choosing between them

| Your data is | Use |
| --------------------------------- | --------------------------- |
| A file on disk | `read_csv` and its relatives |
| Organised by column | A dictionary of lists |
| Arriving as records, one at a time | A list of dictionaries |
| The output of NumPy computation | The array, plus `columns` |
| Rows accumulated in a loop | A list of dictionaries, converted once at the end |

That last row is a habit worth adopting now. Appending to a DataFrame inside a loop copies the entire table on every iteration, and on a few thousand rows it becomes noticeably slow.

```python
# avoid
result = pd.DataFrame()
for item in items:
    result = pd.concat([result, pd.DataFrame([row_dict])])

# prefer
rows = []
for item in items:
    rows.append(row_dict)
result = pd.DataFrame(rows)
```

Collect into a list, convert once. The second version is shorter and dramatically faster.

> Building a DataFrame row by row is the most common performance mistake beginners make in pandas, and it is invisible until the data grows.

## Setting the index while you build

```python
pd.DataFrame({'mass': [3750, 5000]}, index=['bird_1', 'bird_2'])
```

Supplying an index at construction is worth doing whenever your rows have real identifiers: student IDs, dates, station codes. It makes lookups direct and makes alignment with other tables automatic.

## Types at construction

pandas infers a type per column from the values it sees. Two inferences are worth watching.

A column of whole numbers containing one missing value becomes floats, because a `NaN` cannot be stored among integers in the traditional representation.

A column where one value is text becomes a text column entirely, and all arithmetic on it fails. This is how a single stray entry such as "N/A" or "not recorded" turns a measurement column into something unusable, and it is the most common cause of a numeric column arriving as text from a file.

## Practise the round trip

Take a small table you know: five rows of anything.

Build it three ways: as a dictionary of lists, as a list of dictionaries, and from a NumPy array with column names. Confirm all three produce the same thing with `.equals()`.

Then add a `None` into one numeric column and rebuild. Watch the dtype change from integer to float, and note that nothing warned you.
