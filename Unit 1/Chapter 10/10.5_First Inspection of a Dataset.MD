## The five minutes before any analysis

A file has just loaded. Before asking it anything, find out what it is: how big, what columns, what types, what is missing, and what the values look like.

Five methods answer all of that, and running them is not preparation for the work. It is the first part of it.

## head and tail

```python
import pandas as pd
df = pd.read_csv('penguins.csv')
df.head(3)
```

```
  species     island  bill_length_mm  bill_depth_mm  flipper_length_mm  body_mass_g     sex  year
0  Adelie  Torgersen            39.1           18.7              181.0       3750.0    male  2007
1  Adelie  Torgersen            39.5           17.4              186.0       3800.0  female  2007
2  Adelie  Torgersen            40.3           18.0              195.0       3250.0  female  2007
```

```python
df.tail(3)
```

```
       species island  bill_length_mm  bill_depth_mm  flipper_length_mm  body_mass_g     sex  year
341  Chinstrap  Dream            49.6           18.2              193.0       3775.0    male  2009
342  Chinstrap  Dream            50.8           19.0              210.0       4100.0    male  2009
343  Chinstrap  Dream            50.2           18.7              198.0       3775.0  female  2009
```

Check both ends, not just the top. Files often carry a total row at the bottom, or trail off into blank rows, and `head` alone will never show you.

Notice something the two views reveal together: the file opens with Adelie on Torgersen and closes with Chinstrap on Dream. It is sorted by species, which matters if you ever split it without shuffling.

`df.sample(3, random_state=1)` draws random rows instead, and it is worth running too, since the middle of a file can differ from both ends.

## describe

```python
df.describe().round(2)
```

```
       bill_length_mm  bill_depth_mm  flipper_length_mm  body_mass_g     year
count          342.00         342.00             342.00       342.00   344.00
mean            43.92          17.15             200.92      4201.75  2008.03
std              5.46           1.97              14.06       801.95     0.82
min             32.10          13.10             172.00      2700.00  2007.00
25%             39.22          15.60             190.00      3550.00  2007.00
50%             44.45          17.30             197.00      4050.00  2008.00
75%             48.50          18.70             213.00      4750.00  2009.00
max             59.60          21.50             231.00      6300.00  2009.00
```

Eight numbers per numeric column, and each row of that table is a check you already know how to make.

Compare `mean` against the 50% row: 4,201.75 against 4,050 for body mass says the distribution leans right. Read `min` and `max` against what is physically possible. Take the 25% and 75% rows as quartiles and the gap between them as the interquartile range.

Note what `describe` did with `year`. It is stored as an integer, so pandas computed a mean of 2008.03, which means nothing. The method summarises every numeric column whether or not the summary makes sense.

## Counting categories

```python
df['sex'].value_counts(dropna=False)
```

```
sex
male      168
female    165
NaN        11
```

`value_counts` on every text column is where spelling variants, unexpected categories, and stray codes appear. Pass `dropna=False` or missing values are silently omitted from the count.

## Counting what is missing

```python
df.isna().sum()
```

```
bill_length_mm        2
bill_depth_mm         2
flipper_length_mm     2
body_mass_g           2
sex                  11
```

Per-column counts of missing values. Add `.mean()` instead of `.sum()` for proportions, which is easier to judge on a large file.

The pattern here is informative on its own. Four columns missing exactly two values suggests two rows missing everything, rather than scattered gaps, and one line confirms it: `df[df['body_mass_g'].isna()]` returns those two rows.

> Missing values clustered in the same rows mean a different problem from missing values scattered across the file, and the counts alone cannot tell you which you have.

## The routine

| Step | Command | What you learn |
| ---- | ------------------------------- | -------------------------------- |
| 1 | `df.shape` | Does the size match expectations |
| 2 | `df.head()` and `df.tail()` | What the data looks like, and what is at the ends |
| 3 | `df.info()` | Types and completeness in one view |
| 4 | `df.describe()` | Ranges, centres, and impossible values |
| 5 | `value_counts()` per text column | Categories, spellings, surprises |
| 6 | `df.isna().sum()` | Where the gaps are |

Six commands, two minutes, and you can describe the file to someone else.

## Practise on something unfamiliar

Download a dataset you have never seen from a public portal and run all six steps without reading any documentation first.

Then write five sentences describing the file, and only then open the documentation.

The gaps between what you inferred and what the documentation says are the columns that will surprise you later, and finding them in the first five minutes is exactly the point of the routine.
