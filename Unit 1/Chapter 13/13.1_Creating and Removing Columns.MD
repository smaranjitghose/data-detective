## Deriving what the file did not record

The penguin file records body mass in grams. If your report is in kilograms, or your comparison needs a ratio of two measurements, those columns do not exist and you make them.

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

df['mass_kg'] = df['body_mass_g'] / 1000
df['bill_ratio'] = (df['bill_length_mm'] / df['bill_depth_mm']).round(3)
```

```
  species  body_mass_g  mass_kg  bill_ratio
0  Adelie       3750.0     3.75       2.091
1  Adelie       3800.0     3.80       2.270
2  Adelie       3250.0     3.25       2.239
```

Assignment to a name that does not exist creates the column, computed for every row at once with no loop. It lands at the end of the table.

## Columns come from four sources

| Source | Example |
| ---------------------------- | ---------------------------------------- |
| Arithmetic on other columns | `mass_kg`, `bill_ratio`, a percentage |
| A condition | `heavy = mass > 5000` |
| Splitting an existing column | State code extracted from a registration number |
| A summary joined back on | Each bird's mass minus its species average |

The second is worth showing because it is so common:

```python
df['heavy'] = df['body_mass_g'] > 5000
df['heavy'].sum()      # 61
```

A boolean column is a column like any other. Summing it counts the True values, and averaging it gives the proportion, which is the fastest way to answer "what share of rows are like this".

## Removing

```python
df = df.drop(columns=['year'])
```

`drop` returns a new DataFrame and leaves the original alone, so the result has to be assigned or nothing changes. Passing a list removes several at once.

Older code writes `inplace=True` instead of assigning. It saves no memory in practice, it prevents chaining, and it is falling out of use. Prefer the assignment.

## Position, when it matters

New columns append at the end, which is usually fine. When it is not:

```python
df.insert(0, 'row_id', range(len(df)))
df.columns[:3]        # ['row_id', 'species', 'island']
```

`insert` takes a position, a name, and the values. It is the one operation here that modifies the DataFrame directly rather than returning a copy.

For a wholesale rearrangement, selecting columns in the order you want is simpler: `df[['species', 'mass_kg', 'body_mass_g']]`.

## assign, and why chaining reads better

```python
out = (pd.read_csv('penguins.csv')
       .assign(mass_kg=lambda d: d['body_mass_g'] / 1000,
               heavy=lambda d: d['mass_kg'] > 5)
       .loc[:, ['species', 'mass_kg', 'heavy']])
```

```
  species  mass_kg  heavy
0  Adelie     3.75  False
1  Adelie     3.80  False
2  Adelie     3.25  False
```

`assign` returns a new DataFrame with the columns added, which lets the whole sequence be one expression from file to result.

Two details make it work. The lambda receives the DataFrame as it stands at that point, so `heavy` can refer to `mass_kg` created in the same call. And nothing is modified in place, so re-running the cell gives the same answer, which is not true of a notebook full of `df['x'] = ...` lines executed in an order you no longer remember.

That reproducibility is the real argument for it. A chained expression run twice produces the same result; a sequence of in-place mutations depends on how many times each cell ran.

## Naming, briefly

Names you will type fifty times deserve a moment's thought. Lowercase, underscores, no spaces, and a unit where the unit is not obvious.

`mass_kg` is better than `mass` because the next person does not have to check. `bill_ratio` is worse than `bill_length_to_depth`, and shorter, which is the trade you are making.

> A derived column carries an assumption. `mass_kg` assumes grams were the input; a per-capita figure assumes a population column matched correctly. Record the assumption near the code, because the column name cannot carry it.

## Overwriting, and when not to

```python
df['body_mass_g'] = df['body_mass_g'] / 1000     # now the name lies
```

Overwriting a column with a transformed version leaves a name that no longer describes its contents, and anyone reading later has no way to know. Write to a new name and drop the original if you must.

The exception is cleaning, where the intent is to replace a value with its corrected form. Standardising a text column in place is normal; converting units in place is not.

## Practise the chain

Take any file and produce three derived columns: one from arithmetic, one from a condition, and one from splitting an existing column.

Write it twice, once as a sequence of bracket assignments and once as a single `assign` chain.

Then restart your kernel and run only the second version. It should reproduce exactly, which is the property the first version lacks the moment you have run its cells out of order.
