## Turning a measurement into a category

Body mass is a continuous measurement running from 2,700 to 6,300 grams. Sometimes you want three or four size bands instead: to cross-tabulate against species, to report shares rather than averages, or because the decision the analysis feeds is itself banded.

pandas has two functions for this, and choosing between them is the whole topic.

## cut, for boundaries you decide

```python
import pandas as pd
df = pd.read_csv('penguins.csv')

bands = pd.cut(df['body_mass_g'],
               bins=[0, 3500, 4500, 5500, 7000],
               labels=['light', 'medium', 'heavy', 'very heavy'])
bands.value_counts().sort_index()
```

```
light          78
medium        149
heavy          87
very heavy     28
```

You supply the edges and the labels. Four edges plus a fifth gives four bins, and each value lands in the interval containing it.

The bins are right-closed by default, so a bird at exactly 3,500 grams goes into `light` rather than `medium`. Pass `right=False` to reverse that. Boundary rules matter whenever a threshold has consequences, and the default is easy to overlook.

Values outside the outermost edges become missing rather than raising an error, which is why the edges here run to 0 and 7,000 rather than to the observed minimum and maximum.

## cut with a number instead of edges

```python
pd.cut(df['body_mass_g'], 4)
```

```
(2696.4, 3600.0]  (3600.0, 4500.0]  (4500.0, 5400.0]  (5400.0, 6300.0]
```

Passing an integer divides the range into that many equal-width intervals. The edges come out at awkward numbers, and the counts in each are whatever the data puts there.

Equal-width bins on a skewed column produce a first bin holding almost everything and a last bin holding three rows. That is sometimes exactly what you want to show and rarely what you want to analyse.

## qcut, for equal-sized groups

```python
pd.qcut(df['body_mass_g'], 4, labels=['Q1', 'Q2', 'Q3', 'Q4']).value_counts().sort_index()
```

```
Q1    89
Q2    87
Q3    81
Q4    85
```

`qcut` chooses the edges so that each bin holds roughly the same number of rows. The counts are near-equal by construction; the widths are not.

```python
pd.qcut(df['body_mass_g'], 4, retbins=True)[1]
```

```
[2700.0, 3550.0, 4050.0, 4750.0, 6300.0]
```

Those edges are the quartiles from the earlier statistics unit, which is exactly what they are: `qcut` with 4 bins is a quartile split, and with 10 it is a decile split.

The counts are not exactly equal because repeated values cannot be divided across a boundary.

## Choosing between them

| | `cut` | `qcut` |
| ------------------ | ------------------------------- | ------------------------------ |
| You supply | The boundaries | The number of groups |
| Bins have equal | Width | Population |
| Suits | Meaningful thresholds | Ranking and comparison |
| On skewed data | Very uneven counts | Even counts, uneven widths |
| Edges are stable across files | Yes | No, they follow the data |

That last row decides a lot of real cases. A grade boundary at 40 marks is the same 40 next year; a bottom-quartile boundary moves whenever the data moves, so "bottom quartile" this year and last year are not the same score.

Use `cut` when the thresholds mean something outside the data: a pass mark, a legal limit, a price tier. Use `qcut` when you want groups of comparable size for comparison.

## What binning is for, and what it costs

The gain is interpretability. Bands cross-tabulate against categories in a way a continuous column cannot:

```python
pd.crosstab(df['species'], bands)
```

```
body_mass_g  light  medium  heavy  very heavy
species
Adelie          59      85      7           0
Chinstrap       19      47      2           0
Gentoo           0      17     78          28
```

That table says in one view what the earlier units took several statistics to establish. No Gentoo is light, no Adelie or Chinstrap is very heavy, and the two smaller species overlap almost entirely.

The cost is information. Every value inside a band becomes indistinguishable from every other, so a 3,501 gram bird and a 4,499 gram bird are both "medium" while the 3,499 gram bird next to the first one is "light".

> Binning throws away detail on purpose. Doing it before you have looked at the distribution throws away the detail that would have told you where the boundaries should be.

## The result is a category

```python
bands.dtype        # category
```

Categorical columns use far less memory than text, sort in the order you defined rather than alphabetically, and remember which categories exist even when none are present in a filtered subset.

That last property is useful and occasionally surprising: a `value_counts()` on a filtered categorical column shows zero-count categories, which is usually what you want in a report.

## Practise both on the same column

Take a skewed numeric column and bin it twice: four equal-width bins with `cut`, and four equal-population bins with `qcut`.

Print both sets of counts and both sets of edges.

Then cross-tabulate each against a category column. One of the two will produce a readable table and the other will produce a table with a nearly empty row, and which is which tells you something about the shape of the column you started with.
