## Making values comparable before you compare them

```
        student        city
0    Ravi Kumar   Hyderabad
1    ravi kumar   hyderabad
2      Priya S.   Bengaluru
3      ANJALI R   Bangalore
4      Priya S.   Bengaluru
```

```python
raw['city'].value_counts()
```

```
{'Bengaluru': 2, 'Hyderabad': 1, 'hyderabad ': 1, 'Bangalore': 1}
```

Four categories where there are two cities. One is a trailing space, invisible on screen and decisive to every comparison. The other is a genuine alternative name for the same place.

Group by this column and you get four groups. Join on it and half the rows fail to match. Nothing will object.

## The str accessor

Every string method is available on a text column through `.str`, applied to every value at once.

```python
raw['student'].str.strip().str.lower().str.title()
```

```
        student student_clean
0    Ravi Kumar    Ravi Kumar
1    ravi kumar    Ravi Kumar
2      Priya S.      Priya S.
3      ANJALI R      Anjali R
4      Priya S.      Priya S.
```

Three operations chained: remove surrounding whitespace, lowercase everything, then capitalise each word. The two Ravi entries now match exactly.

Missing values pass through untouched rather than causing an error, which is convenient and means the result can still contain gaps.

## The methods worth knowing

| Method | Does |
| ----------------------- | ------------------------------------ |
| `.str.strip()` | Removes leading and trailing whitespace |
| `.str.lower()`, `.str.upper()` | Changes case |
| `.str.title()` | Capitalises each word |
| `.str.replace(a, b)` | Substitutes text |
| `.str.contains('x')` | True where the value contains x |
| `.str.startswith('A')` | True where it begins with A |
| `.str.split(',')` | Splits into a list |
| `.str.len()` | Length of each value |
| `.str.extract(r'(\d+)')` | Pulls out a pattern |

`.str.strip()` first, always. Whitespace is the problem you cannot see, and it defeats every subsequent comparison.

## Synonyms need a mapping, not a method

Whitespace and case are mechanical. Bengaluru and Bangalore are not, and no string method will merge them.

```python
raw['city_clean'] = (raw['city']
                     .str.strip()
                     .str.title()
                     .replace({'Bangalore': 'Bengaluru'}))
```

```
before: {'Bengaluru': 2, 'Hyderabad': 1, 'hyderabad ': 1, 'Bangalore': 1}
after:  {'Bengaluru': 3, 'Hyderabad': 2}
```

Four categories became two. The mechanical cleaning handled Hyderabad; the explicit mapping handled Bengaluru.

Building that mapping requires domain knowledge, and the way to find what belongs in it is to read the output of `value_counts()` in full. Sorting alphabetically puts variants next to each other, which makes them easy to spot.

> Reading every distinct value of a category column, once, is the cheapest quality check in pandas. It exposes whitespace, case variants, synonyms, and codes nobody documented.

## Why this must come first

Standardisation precedes grouping, counting, joining, and deduplicating, because all four compare values exactly.

On the student table, deduplicating before cleaning finds one repeated row. After cleaning it finds two, because the second Ravi row was only different in capitalisation. The order changed the answer.

The same applies to a join. Two files, one storing `Bengaluru` and one storing `Bangalore`, will match on nothing, and the result is a table missing rows with no error to explain them.

## Pulling structure out of text

```python
df['code'].str.extract(r'([A-Z]{2})(\d+)')
```

Regular expressions retrieve parts of a value: a state code from a registration number, a year from a file name, a unit from a measurement stored as text.

`.str.extract` returns a DataFrame with one column per capture group, which makes it the tool for splitting a compound identifier into its parts.

For simpler cases `.str.split()` with an index is enough: `df['name'].str.split(' ').str[0]` gives the first word of each value.

## Checking your cleaning worked

Three counts, before and after: the number of distinct values, the number of rows, and the number of missing values.

Distinct values should drop, since that is the point. Row count should not change at all, since standardising modifies values rather than removing records. Missing count should not change either, unless you deliberately converted something to missing.

Any movement in the second or third number means your cleaning did something you did not intend.

## Practise on a category column

Take a text column from any real file and print its `value_counts()` in full, sorted by name rather than frequency.

Standardise mechanically first: strip, then case. Count distinct values again.

Then read what remains and write the mapping dictionary for the synonyms only a human can identify. The number of categories you started with, after mechanical cleaning, and after mapping is a useful three-number summary of how much work the column needed.
