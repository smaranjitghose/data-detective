## Making a column into what it should have been

A column arrives as text when it holds numbers, or as numbers when it holds identifiers, or as text when it holds dates. Until the type is right, nothing else works.

```python
raw['marks']
```

```
0              78
1              82
2    not recorded
3              91
4              88
```

```python
raw['marks'].mean()
```

```
TypeError: Cannot perform reduction 'mean' with string dtype
```

One non-numeric value in five turned the whole column to text. This is the single most common type problem in real files.

## to_numeric with coercion

```python
pd.to_numeric(raw['marks'], errors='coerce')
```

```
0    78.0
1    82.0
2     NaN
3    91.0
4    88.0
```

```python
raw['marks_num'].mean()      # 84.75
```

`errors='coerce'` converts what it can and turns the rest into missing values. The unusable entry becomes a gap, which is honest: the value was never a number.

The alternatives are `errors='raise'`, the default, which stops on the first bad value, and no coercion at all, which leaves you where you started. Coercion is usually right, and it is worth counting the new gaps afterwards to see how much you converted away:

```python
converted.isna().sum() - original.isna().sum()
```

If that number is large, the column has a systematic problem rather than a few stray entries.

## astype, for clean columns

```python
df['year'].astype('int16')
df['species'].astype('category')
```

`astype` converts directly and fails on anything it cannot handle. Use it when you know the column is clean and you are choosing a representation.

Two conversions repay themselves on large files:

| Conversion | Memory before | Memory after |
| ------------------------ | ------------: | -----------: |
| `year` int64 to int16 | 2,884 bytes | 820 bytes |
| `species` text to category | 19,256 bytes | 644 bytes |

The category conversion is dramatic because a text column stores the full string for every row, while a category stores each distinct value once plus a small code per row. On a column with a few distinct values repeated across millions of rows, this is the difference between fitting in memory and not.

## astype and missing values

```python
df['body_mass_g'].astype('int64')
```

```
IntCastingNaNError: Cannot convert non-finite values (NA or inf) to integer.
```

A traditional integer column cannot hold a missing value, which is why body mass loaded as a float despite being recorded in whole grams.

The nullable integer type solves this:

```python
df['body_mass_g'].astype('Int64').head(4)      # [3750, 3800, 3250, <NA>]
```

Capital `Int64` rather than lowercase. It holds whole numbers and missing values together, which is what you usually want for counts and identifiers that have gaps.

## Dates, and a trap worth seeing

```python
pd.to_datetime(raw['joined'], format='mixed', dayfirst=True)
```

```
0   2023-02-01
1   2023-03-02
2   2023-03-15
3   2023-03-20
4   2023-03-15
```

Look at row 1. The input was `2023-02-03`, an unambiguous ISO date meaning 3 February. The output says 2 March.

`dayfirst=True` was applied to a format where it should not have been, and the day and month swapped. No error, no warning, and the row is now a month out.

This is why mixed date formats in one column are dangerous. The safe approach is to identify the formats present, convert each group with an explicit `format` string, and combine the results.

```python
pd.to_datetime(col, format='%d/%m/%Y', errors='coerce')
```

An explicit format converts what matches and coerces the rest to missing, which you can then handle separately. It is more work than `format='mixed'` and it cannot silently misread anything.

## Identifiers should be text

Pin codes, roll numbers, phone numbers, and account codes look numeric and are not quantities.

Stored as numbers they lose leading zeros, so 06821 becomes 6821, and they invite meaningless arithmetic. Convert them at read time with `dtype={'pincode': 'str'}` rather than repairing them afterwards, because the leading zeros are gone by then.

> A column's type should reflect what it means, not what its characters look like. Numbers that will never be added are text.

## Practise on a column that fights you

Find a numeric-looking column that loaded as text.

Use `pd.to_numeric(col, errors='coerce')` and count how many new missing values appear. Then look at the actual values that failed, using `col[pd.to_numeric(col, errors='coerce').isna() & col.notna()]`.

Those values are the interesting part. They will be currency symbols, thousands separators, footnote markers, or the word "nil", and each one tells you something about how the file was produced.
