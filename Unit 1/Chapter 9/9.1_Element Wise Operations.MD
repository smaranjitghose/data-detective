## Arithmetic on whole arrays at once

In plain Python, adding two lists of numbers means writing a loop. In NumPy you write the arithmetic and it applies to every element.

```python
import numpy as np
a = np.array([1, 2, 3, 4])
b = np.array([10, 20, 30, 40])

a + b        # [11 22 33 44]
a * b        # [ 10  40  90 160]
b - a        # [ 9 18 27 36]
b / a        # [10. 10. 10. 10.]
a ** 2       # [ 1  4  9 16]
```

Each operation pairs up elements by position: the first with the first, the second with the second. This is what element-wise means, and it covers every arithmetic operator.

Notice `b / a` returning floats with decimal points even though both inputs were integers. Division always produces floats in NumPy, which is the same rule Python 3 uses.

## Multiplication is not matrix multiplication

`a * b` multiplies matching positions. It does not perform the matrix product, which uses the `@` operator or `np.dot`.

For anyone arriving from a linear algebra course this is the reverse of what you expect, and it is worth fixing in memory now. In NumPy, the plain operators are element-wise and matrix operations have their own symbol.

## Comparisons work the same way

```python
a > 2        # [False False  True  True]
```

A comparison returns an array of booleans, one per element, rather than a single True or False. That array is useful in its own right, and it underpins filtering.

## Functions apply element-wise too

```python
np.sqrt(b)      # [3.162 4.472 5.477 6.325]
```

NumPy provides its own versions of the mathematical functions, and they operate on whole arrays. `np.sqrt`, `np.log`, `np.exp`, `np.sin`, `np.abs`, and `np.round` all follow this pattern.

These are called universal functions, or ufuncs. Python's built-in `math.sqrt` accepts one number at a time and will refuse an array, so use the NumPy version whenever you are working with arrays.

| Operation | What it does |
| --------------- | ------------------------------------ |
| `a + b` | Adds matching positions |
| `a * b` | Multiplies matching positions |
| `a @ b` | Matrix product |
| `np.sqrt(a)` | Square root of every element |
| `np.round(a, 2)` | Rounds every element |
| `a > 2` | A boolean per element |

## Scalars apply to everything

```python
a * 10       # [10 20 30 40]
a + 100      # [101 102 103 104]
```

A single number combines with every element. This is the simplest case of the broadcasting rules that come next, and it is the one people use constantly: converting units, shifting a baseline, scaling a column.

> Writing `arr * 10` instead of a loop is not just shorter. It hands the work to compiled code, and on a large array that is the difference between milliseconds and seconds.

## Shapes have to be compatible

```python
np.array([1, 2, 3]) + np.array([1, 2])
```

```
ValueError: operands could not be broadcast together with shapes (3,) (2,)
```

Three elements and two elements cannot be paired up, so the operation fails. The error message names both shapes, which makes it one of the more helpful errors in Python.

When you see this message, print the shapes of both operands. The mismatch is almost always somewhere upstream, in a filter that removed a different number of rows than you expected.

## Chaining operations

Expressions combine as you would expect, and each step produces a new array.

```python
scores = np.array([45, 62, 78, 91])
scaled = (scores - scores.min()) / (scores.max() - scores.min())
```

That line rescales the values to run from 0 to 1, using two aggregations and two element-wise operations, with no loop and no intermediate variables.

Each operation does allocate a new array, so a long chain over a very large array uses more memory than you might expect. For ordinary work this does not matter; for arrays of hundreds of millions of elements it does, and NumPy offers in-place forms such as `a += 1` for those cases.

## Practise the translation

Take three loops you have written that walk through a list doing arithmetic: converting units, computing a percentage, applying a threshold.

Rewrite each as a single NumPy expression with no loop.

Then time both versions on a hundred thousand elements. The exercise is less about the speed than about the habit of seeing an operation on a whole column rather than a sequence of steps over elements.
