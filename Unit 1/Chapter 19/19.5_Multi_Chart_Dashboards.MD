## Several charts in one view

A dashboard is several charts arranged so a reader can see them together. Plotly builds them two ways: a static arrangement of panels, or an application that responds to input.

## Subplots

```python
from plotly.subplots import make_subplots
import plotly.graph_objects as go

fig = make_subplots(rows=1, cols=2,
                    subplot_titles=('Mass by species', 'Flipper against mass'))

fig.add_trace(go.Box(x=df['species'], y=df['body_mass_g']), row=1, col=1)
fig.add_trace(go.Scatter(x=df['flipper_length_mm'], y=df['body_mass_g'],
                         mode='markers'), row=1, col=2)

fig.update_layout(height=400, width=900, showlegend=False)
```

`make_subplots` creates the grid and each `add_trace` places a chart into a numbered cell, counting from 1 rather than 0.

Note that this uses `graph_objects` rather than `express`. Plotly Express builds complete figures, so combining several of them into one layout means dropping to the lower-level interface. Extracting a trace from an Express figure is possible and awkward; building the pieces directly is cleaner.

## Layout options

| Argument | Does |
| ----------------- | ------------------------------------- |
| `rows`, `cols` | Grid dimensions |
| `subplot_titles` | A title per panel |
| `shared_xaxes` | Linked horizontal axes |
| `shared_yaxes` | Linked vertical axes |
| `specs` | Per-cell settings, including secondary axes and map types |
| `vertical_spacing` | Gap between rows |

Shared axes matter here for the same reason they did in the Matplotlib unit, plus one more: in an interactive chart, shared axes link the zoom, so exploring one panel moves the others with it.

That linkage is the main thing a Plotly dashboard offers over a static grid of images.

## What a good dashboard does

Three or four charts answering one question, arranged so the eye moves between them in a sensible order.

The common failure is the opposite: twelve charts answering twelve questions, arranged by whatever fitted. A reader facing that takes an impression of thoroughness and no specific finding, which is the same criticism the visualisation principles unit made of a wall of small multiples.

| Good dashboard | Poor dashboard |
| ------------------------------ | ------------------------------------ |
| One question, several angles | Every chart anyone asked for |
| Consistent colours throughout | Each chart with its own palette |
| A clear reading order | An arbitrary grid |
| Three to six charts | Twelve or more |
| Each chart carries a finding | Charts included because the data exists |

Consistent colour is the cheapest improvement. If Gentoo is green in one panel, it must be green in all of them, and an explicit colour dictionary is how you guarantee it.

## Interactive dashboards need a server

Everything above produces a static HTML file: the charts respond to hovering and zooming, and nothing recalculates.

A dashboard with dropdowns, date pickers, or filters that change what is computed requires a running application, which is what Dash provides. That is a step beyond a chart, involving callbacks, a server process, and deployment.

The intermediate option is worth knowing:

```python
fig.update_layout(
    updatemenus=[dict(buttons=[
        dict(label='All', method='update', args=[{'visible': [True, True, True]}]),
        dict(label='Gentoo only', method='update', args=[{'visible': [False, False, True]}])
    ])])
```

Buttons that toggle which traces are visible work in a plain HTML file, because they only show and hide data already present. Anything requiring new computation does not.

> A single HTML file can filter what is already drawn. Changing what is calculated needs a server, and that is a different project with hosting and maintenance attached.

## Sharing the result

```python
fig.write_html('dashboard.html', include_plotlyjs='cdn')
```

The resulting file opens in any browser with no installation, which is what makes this format useful for sharing with people who do not run Python.

With the library embedded, the file exceeds four megabytes. With `cdn`, it is around 23 kilobytes and needs an internet connection to render. For email, use the CDN version and say so.

## Practise the single question

Take a dataset and write down one question a reader should be able to answer.

Build three charts that together answer it, place them in one layout with shared colours, and give each a title stating what it shows.

Then remove any chart that does not contribute to the question, even if it is a good chart. That removal is what separates a dashboard from a collection, and it is the part most dashboards skip.
